# แบบฝึกหัดที่ 34 · งบโทเค็นของลูกทีม

ผลจากการรันจริง 1 ครั้ง ผลของแต่ละคนจะต่างกันไปตามบัญชี รุ่น และวันที่รัน

## พรอมต์

```text
ใช้สกิล agent-team ใน container multi-account ตั้งงบโทเค็นให้ลูกทีม งานทุกชิ้นใช้ความยาก 1
1. งาน 4 ชิ้นทำต่อกันเป็นลำดับ ให้ค่าย Claude ทำทั้งหมดโดยไม่เจาะจงบัญชี: เขียนกลอนสั้น 4 บรรทัดเกี่ยวกับ ฤดูร้อน ฤดูฝน ฤดูหนาว และวันหยุด ชิ้นละ 1 เรื่อง
2. ตั้งงบโทเค็นของ yolo1 ให้ต่ำพอที่จะเต็มหลังทำงานแรก
สรุปเป็นตาราง: งาน | บัญชี | โทเค็นสะสมของบัญชีนั้น แล้วบอกว่า yolo1 หยุดรับงานใหม่เมื่อไร และงานที่เหลือไปที่บัญชีไหน เก็บแผนงานที่ใช้ไว้ที่ ./exercises/34
```

## คำตอบของ Claude

ฉันรันงานจริงครบแล้ว กลอนทั้ง 4 ชิ้นเสร็จหมด และ yolo1 หยุดรับงานหลังงานแรกตามที่ตั้งไว้ (run `20261124-054147-vizr`)

**วิธีตั้งค่า:** งานทั้ง 4 ชิ้นต่อกันด้วย `depends_on` ทุกชิ้นใช้ `account: "yolo"` (ค่าย Claude ไม่ระบุบัญชี) และ `difficulty: 1` ซึ่งได้รุ่น haiku/low ส่วนงบของ yolo1 ตั้งเป็น `--worker-token-budget yolo1=1`

**จุดที่ควรรู้:** ระบบเลือกบัญชีที่ใช้โควตาไปน้อยที่สุดก่อน ถ้าเปิดทุกบัญชี งานแรกจะไปที่ yolo2 (ใช้ไป 1%) ไม่ใช่ yolo1 (ใช้ไป 30%) ฉันจึงจำกัดลูกทีมไว้แค่ `--workers yolo1,yolo3` (yolo3 ใช้ไป 47%) yolo1 จึงได้งานแรก

| งาน | บัญชี | โทเค็นสะสมของบัญชีนั้น |
|---|---|---|
| summer (ฤดูร้อน) | yolo1 | 19,080 |
| rainy (ฤดูฝน) | yolo3 | 18,017 |
| winter (ฤดูหนาว) | yolo3 | 33,376 |
| holiday (วันหยุด) | yolo3 | 50,485 |

โทเค็นที่นับกับงบคือ input + cache write + output ไม่นับ cache read

- **yolo1 หยุดรับงานใหม่เมื่อไร:** เวลา 05:41:57 ทันทีที่ summer เสร็จ เพราะใช้ไป 19,080 เกินงบ 1
- **งานที่เหลือไปที่ไหน:** ทั้งหมดไปที่ yolo3 แผนเดิมให้ rainy กับ holiday ไปที่ yolo1 จึงถูกย้ายมา yolo3 ส่วน winter เป็นของ yolo3 อยู่แล้ว ทั้งสามงานเสร็จปกติ
