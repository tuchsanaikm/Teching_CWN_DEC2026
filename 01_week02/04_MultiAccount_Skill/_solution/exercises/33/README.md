# แบบฝึก 33: บัญชีที่เจาะจงไว้โควตาหมด

แผนงาน: `graph.json` มีงาน A (`account: gyolo1`) ตั้งชื่อร้านดอกไม้ และงาน B (`account: yolo1`, `depends_on: [A]`) เขียนสโลแกน ทั้งสองงานใช้ `difficulty: 1`

```bash
T=//root/ai-accounts/.Claude/shared/skills/agent-team/scripts/team.py
cat graph.json | docker exec -i multi-account python3 $T run - --simulate-limit gyolo1   # run1.log
docker exec multi-account python3 $T run --resume 20261124-054632-gdhf                 # run2.log
```

run id: `20261124-054632-gdhf` (สำเนาอยู่ใน `run/`)

| งาน | รอบแรก (จำลอง gyolo1 โควตาหมด) | รอบที่รันต่อ (ไม่จำลอง) |
|---|---|---|
| A (gyolo1) | failed: limit (จำลอง), 0.1 วินาที, 0 tokens, ไม่ย้ายบัญชี | ok, gyolo1 gemini-3.8-flash-low, 8.0 วินาที → "ผกาพรรณ" |
| B (yolo1) | blocked: งาน A ที่ต้องรอล้ม จึงไม่ได้รัน | ok, yolo1 haiku/low, 3.2 วินาที → "ผกาพรรณ ดอกไม้ทุกช่อ เบ่งบานรอยยิ้มทุกวัน" |

ทำไมงาน A ไม่ถูกย้ายไปบัญชีอื่น: `account: "gyolo1"` คือการเจาะจงบัญชี router จะย้ายงานเมื่อโควตาหมดก็ต่อเมื่อระบุแค่ฝั่ง (`gyolo` ย้ายได้ภายในฝั่ง) หรือ `any` (ย้ายข้ามฝั่งได้) ถ้าเจาะจงบัญชีไว้ งานจะล้มพร้อมบอกเหตุผล ไม่ย้ายไปบัญชีอื่นแบบเงียบ ๆ เพราะผู้ใช้อาจเลือกบัญชีนั้นด้วยเหตุผลบางอย่าง เช่น รุ่นโมเดล ค่าใช้จ่าย หรือสิทธิ์เข้าถึง นอกจากนี้กราฟนี้เจาะจงบัญชีทุกงาน รายชื่อบัญชีที่ใช้ได้จึงมีแค่ gyolo1 และ yolo1 ไม่มีบัญชีสำรองในฝั่ง gyolo ให้ย้ายไปอยู่แล้ว B จึงถูกบล็อกตามไปด้วย ส่วน `--resume` ที่ไม่ใส่ `--simulate-limit` จะรันจริงและรันเฉพาะงานที่ยังไม่สำเร็จ
