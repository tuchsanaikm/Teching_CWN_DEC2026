# แบบฝึกหัดที่ 5 · อ่านไฟล์ยาว

ผลจากการรันจริง 1 ครั้ง ผลของแต่ละคนจะต่างกันไปตามบัญชี รุ่น และวันที่รัน

## พรอมต์

```text
ใช้สกิล yolo และ gyolo ใน container multi-account ทดสอบการอ่านไฟล์ยาว ทำในโฟลเดอร์งาน ex/05 ใน container
1. สร้างไฟล์ log.txt ยาว 1,500 บรรทัด เป็นบันทึกการทำงานของเซิร์ฟเวอร์สมมติ และซ่อนบรรทัด "ERROR รหัส 7741 ที่เครื่อง db-3" ไว้ 1 บรรทัดกลางไฟล์
2. ให้ yolo1 และ gyolo1 อ่านไฟล์นั้น แล้วตอบว่า ERROR เกิดที่เครื่องไหน รหัสอะไร และอยู่บรรทัดที่เท่าไร ใช้ความยาก 2
สรุปเป็นตาราง: บัญชี | คำตอบ | ถูกหรือไม่ | เวลา (วินาที) | โทเค็นขาเข้า
```

## คำตอบของ Claude

ทั้งสองบัญชีตอบถูกครบทั้งเครื่อง รหัส และเลขบรรทัด

ไฟล์ทดสอบคือ `/workspace/ex/05/log.txt` ใน container มี 1,500 บรรทัด และซ่อนบรรทัด `ERROR รหัส 7741 ที่เครื่อง db-3` ไว้ที่**บรรทัด 742** ผมตรวจตำแหน่งด้วย `grep -n` แล้ว ทั้งสองบัญชีรันพร้อมกันด้วยความยาก 2 (`-d 2`)

| บัญชี | คำตอบ | ถูกหรือไม่ | เวลา (วินาที) | โทเค็นขาเข้า |
|---|---|---|---|---|
| yolo1 (claude-sonnet-5-5 / medium) | db-3 · รหัส 7741 · บรรทัด 742 | ✅ ถูกทั้ง 3 จุด | 5.13 | 4 (+ อ่านจาก cache 43,422 + เขียน cache 16,134 = 59,560) |
| gyolo1 (gemini-3.8-flash-medium) | db-3 · รหัส 7741 · บรรทัด 742 | ✅ ถูกทั้ง 3 จุด | 11.28 | 41,676 (+ อ่านจาก cache 47,410 = 89,086) |

- **อ่านตัวเลขโทเค็นขาเข้าให้ถูก:** ทั้งสอง CLI ไม่นับโทเค็นที่อ่านจาก cache รวมไว้ใน `input_tokens` ตัวเลข 4 ของ yolo1 จึงเกือบทั้งหมดมาจาก cache ถ้าจะเทียบกัน ให้ดูยอดรวมในวงเล็บ yolo1 ใช้น้อยกว่า gyolo1 ประมาณ 1.5 เท่า
- **ผลอื่น ๆ:** yolo1 เร็วกว่าราวเท่าตัว และราคาตามรายการคือ $0.07 ซึ่งไม่ใช่ยอดที่จ่ายจริง gyolo1 ไม่รายงานราคา และใช้ thinking 330 โทเค็น
- **ไฟล์ log.txt เดิมหาย:** ใน ex/05 มี log.txt จากรอบก่อนอยู่แล้ว ตรงโจทย์เหมือนกัน (ERROR อยู่บรรทัด 750) ผมตั้งใจสำรองเป็น `log.txt.bak` แต่คำสั่งล้มเพราะ Git Bash แปลง path ไฟล์เดิมจึงถูกเขียนทับและกู้คืนไม่ได้ ถ้าต้องการ ผมสร้างแบบเดิมให้ใหม่ได้

ทั้งสองการเรียกถูกบันทึกลง ledger แล้ว ดูย้อนหลังได้ด้วยคำสั่ง `stats`
