# แบบฝึกหัดที่ 2 · คำถามเดียว ถาม 3 ค่าย

ผลจากการรันจริง 1 ครั้ง ผลของแต่ละคนจะต่างกันไปตามบัญชี รุ่น และวันที่รัน

## พรอมต์

```text
ใช้สกิล yolo, cyolo และ gyolo ใน container multi-account ถามคำถามเดียวกันกับ 3 ค่าย ด้วยความยาก 1
1. ถาม yolo1, cyolo1 และ gyolo1 ว่า "Docker volume ต่างจาก bind mount อย่างไร ตอบไม่เกิน 2 ประโยค"
2. เทียบคำตอบของทั้ง 3 ค่าย
สรุปเป็นตาราง: บัญชี | รุ่นที่สกิลเลือก | คำตอบ | เวลา (วินาที) | โทเค็นขาเข้า | โทเค็นขาออก แล้วบอกว่าคำตอบของค่ายไหนชัดที่สุด เพราะอะไร
```

## คำตอบของ Claude

ถามทั้ง 3 บัญชีด้วยความยาก 1 (`-d 1`) แล้ว ตอบสำเร็จครบทุกบัญชี (`ok: true`)

| บัญชี | รุ่นที่สกิลเลือก | คำตอบ | เวลา (วินาที) | โทเค็นขาเข้า | โทเค็นขาออก |
|---|---|---|---|---|---|
| yolo1 (Claude) | haiku / low (`claude-haiku-5-5`) | Volume ถูกจัดการโดย Docker เก็บใน storage ของ Docker เอง (เช่น `/var/lib/docker/volumes/`) เหมาะกับข้อมูลที่ต้องคงอยู่ของ container; bind mount ผูกโฟลเดอร์ใดก็ได้บนเครื่อง host เข้ากับ container โดยตรง เหมาะกับการแชร์ไฟล์หรือแก้โค้ดระหว่างพัฒนา | 3.36 | 2 (+ cache read 14,499, cache write 15,928) | 175 |
| cyolo1 (Codex) | `gpt-6.2-sol` / low | Docker volume คือพื้นที่เก็บข้อมูลที่ Docker จัดการให้และอ้างอิงด้วยชื่อได้ ส่วน bind mount คือการนำไฟล์หรือโฟลเดอร์จากพาธที่ระบุบนเครื่องโฮสต์มาใช้ในคอนเทนเนอร์โดยตรง. Volume เหมาะกับข้อมูลถาวรอย่างฐานข้อมูล ส่วน bind mount เหมาะกับการแชร์ซอร์สโค้ดหรือไฟล์ตั้งค่าจากโฮสต์. | 5.87 | 25,919 (ในนี้เป็น cache read 13,952) | 100 |
| gyolo1 (Gemini) | `gemini-3.8-flash-low` | **Volume** ถูกจัดการโดย Docker ทั้งหมดและจัดเก็บไว้ในพื้นที่เฉพาะของ Docker (แนะนำสำหรับการใช้งานทั่วไปเพื่อความปลอดภัยและการย้ายข้อมูล) ส่วน **Bind mount** เป็นการผูกไฟล์หรือไดเรกทอรีใดก็ได้จากโฮสต์เครื่องจริงเข้ากับคอนเทนเนอร์โดยตรง ซึ่งขึ้นอยู่กับโครงสร้างโฟลเดอร์และสิทธิ์ของระบบปฏิบัติการโฮสต์ | 5.73 | 10,012 | 85 |

ตัวเลขโทเค็นขาเข้าเอามาเทียบกันตรง ๆ ไม่ได้ เพราะแต่ละค่ายนับไม่เหมือนกัน ฝั่ง Claude ตัวเลข input ไม่รวม cache จึงเหลือแค่ 2 แต่จริง ๆ โมเดลอ่าน context ไปราว 30k โทเค็น ฝั่ง Codex ตัวเลข input รวม cache read ไว้แล้ว ส่วน Gemini ครั้งนี้ไม่มี cache เลย

## คำตอบของค่ายไหนชัดที่สุด

**Codex (cyolo1) ชัดที่สุด** เพราะ:
- **ตอบเป็น 2 ประโยค แต่ละประโยคมีหน้าที่ของตัวเอง** ประโยคแรกบอกว่าแต่ละแบบคืออะไร ประโยคที่สองบอกว่าแต่ละแบบเหมาะกับงานแบบไหน ผู้อ่านจึงเทียบกันได้ทีละประเด็น
- **ชี้ความต่างหลักได้ตรงจุด** volume อ้างอิงด้วย "ชื่อ" ส่วน bind mount อ้างอิงด้วย "พาธบนโฮสต์" และยกตัวอย่างการใช้งานที่เห็นภาพ คือฐานข้อมูล กับซอร์สโค้ดหรือไฟล์ตั้งค่า
- ไม่มีวงเล็บหรือข้อความเสริมที่ทำให้อ่านสะดุด

ส่วนอีก 2 ค่าย:
- **Claude** ตอบเร็วที่สุด (3.36 วินาที) และมีพาธตัวอย่างจริงให้เห็น แต่ต่อทุกอย่างไว้ในประโยคเดียวด้วยเครื่องหมาย `;` จึงอ่านแน่นกว่า
- **Gemini** ให้ข้อมูลลึกที่สุด เพราะพูดถึงการพึ่งโครงสร้างโฟลเดอร์และสิทธิ์ของโฮสต์ด้วย แต่ใส่วงเล็บกับตัวหนา ทำให้ประโยคยาว และไม่ได้บอกว่าแต่ละแบบเหมาะกับงานไหนอย่างตรง ๆ
