# แบบฝึกหัดที่ 32 · ลูกทีมโควตาหมดกลางงาน

ผลจากการรันจริง 1 ครั้ง ผลของแต่ละคนจะต่างกันไปตามบัญชี รุ่น และวันที่รัน

## พรอมต์

```text
ใช้สกิล agent-team ใน container multi-account ดูการย้ายงานเมื่อลูกทีมโควตาหมด โดยจำลองเหตุการณ์ ไม่ใช้โควตาจริงจนหมด งานทุกชิ้นใช้ความยาก 1
1. งานเขียนโค้ด 3 ชิ้นที่ไม่ระบุบัญชี: ฟังก์ชัน Python หาค่ามากที่สุด ค่าน้อยที่สุด และค่าเฉลี่ยของรายการตัวเลข ชิ้นละ 1 ฟังก์ชัน
2. จำลองให้ cyolo1 โควตาหมด
สรุปเป็นตาราง: งาน | บัญชีที่ได้รับงานตอนแรก | บัญชีที่ทำจนเสร็จ | เหตุผลที่ย้าย แล้วเก็บแผนงานที่ใช้ไว้ที่ ./exercises/32
```

## คำตอบของ Claude

cyolo1 ไม่ได้เสียโควตาจริงเลย ระบบย้ายงาน 2 ชิ้นของ cyolo1 ไปให้ cyolo2 แล้วทั้ง 3 งานเสร็จครบ การจำลองใช้ `--simulate-limit cyolo1` ให้ทุกการเรียก cyolo1 ล้มทันทีเหมือนโควตาหมด ใช้เวลา 0.1 วินาที 0 tokens

| งาน | บัญชีที่ได้รับงานตอนแรก | บัญชีที่ทำจนเสร็จ | เหตุผลที่ย้าย |
|---|---|---|---|
| find_max | cyolo1 | cyolo2 | cyolo1 ล้มเพราะโควตาหมด (จำลอง) จึงย้ายไปบัญชี Codex อีกบัญชีก่อนข้ามไปค่ายอื่น |
| find_min | cyolo2 | cyolo2 | ไม่ได้ย้าย |
| find_mean | cyolo1 | cyolo2 | cyolo1 ล้มเพราะโควตาหมด (จำลอง) จึงย้ายไปบัญชี Codex อีกบัญชีก่อนข้ามไปค่ายอื่น |

**ทำไมบัญชีแรกเป็น Codex:** ทั้ง 3 งานตั้งเป็นงานเขียนโค้ด ความยาก 1 และไม่ระบุบัญชี ระบบจึงส่งงานโค้ดให้ฝั่ง Codex (cyolo) ก่อน ได้ cyolo1 สองงาน และ cyolo2 หนึ่งงาน

**ทำไมย้ายไป cyolo2:** เมื่อ cyolo1 ล้ม ระบบเลือกบัญชีฝั่งเดียวกันที่ยังว่างก่อน ไม่ต้องข้ามไป Claude หรือ Gemini

**ขอบเขตบัญชี:** ผมจำกัดบัญชีที่ใช้ได้ไว้ที่ cyolo1, cyolo2, yolo2, gyolo1 เพื่อไม่ให้ไปแตะบัญชีอื่น

**ผลการรัน:** run id คือ `20261124-053803-sblo` ฟังก์ชันทั้ง 3 ตัวรับรายการว่างแล้ว raise ValueError ตามที่สั่ง ผมไม่ได้รันทดสอบฟังก์ชันเหล่านี้แยกเอง
