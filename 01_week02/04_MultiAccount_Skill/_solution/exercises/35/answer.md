# แบบฝึกหัดที่ 35 · รอคนอนุมัติ

ผลจากการรันจริง 1 ครั้ง ผลของแต่ละคนจะต่างกันไปตามบัญชี รุ่น และวันที่รัน

## พรอมต์

```text
ใช้สกิล agent-team ใน container multi-account ใส่จุดรออนุมัติในแผนงาน ทำในโฟลเดอร์งาน ex/35 ใน container งานทุกชิ้นใช้ความยาก 1
1. yolo1 เขียนประกาศปิดร้าน 1 วันเพื่อซ่อมแซม บันทึกเป็น notice.md
2. cyolo1 ตรวจคำสะกดในประกาศ ตอบ ผ่าน หรือ ไม่ผ่าน
3. งานสุดท้ายคัดลอก notice.md ไปไว้ในโฟลเดอร์ publish งานนี้ต้องรออนุมัติก่อน
4. เมื่องานหยุดรอ ให้แสดงประกาศและสถานะของทุกงานให้ผมดู แล้วหยุดรอคำตอบจากผม ห้ามอนุมัติเอง
สรุป: สถานะของทุกงานขณะหยุดรอ และสิ่งที่จะเกิดขึ้นเมื่อผมตอบว่าอนุมัติ
```

## คำตอบของ Claude

งานหยุดรออนุมัติอยู่ที่งาน `publish` ฉันยังไม่ได้อนุมัติเอง

**ประกาศ** (`/workspace/ex/35/notice.md` ใน container):

> # ประกาศ: ร้านปิด 1 วันเพื่อซ่อมแซม
>
> เรียนลูกค้าทุกท่าน
>
> ทางร้านขอแจ้งว่า จะปิดให้บริการ **1 วัน** เพื่อทำการซ่อมแซมระบบและสถานที่ให้พร้อมใช้งานต่อไป
>
> ขออภัยในความไม่สะดวกมา ณ ที่นี้ และขอบคุณที่ให้ความไว้วางใจ ทางร้านจะกลับมาเปิดให้บริการตามปกติโดยเร็วที่สุด
>
> ขอบคุณครับ/ค่ะ
> ทางร้าน

**สถานะของทุกงาน** (run `20261124-060222-mdhi` ทุกงานใช้ความยาก 1)

| งาน | บัญชี (รุ่น) | สถานะ | ผล |
|---|---|---|---|
| 1. write | yolo1 (haiku/low) | ok | บันทึก notice.md แล้ว |
| 2. check | cyolo1 (gpt-6.2-sol/low) | ok | **ผ่าน** |
| 3. publish | yolo1 | **waiting_approval** | ยังไม่ทำ ตอนนี้ยังไม่มีโฟลเดอร์ `publish` |

ประกาศไม่ได้ระบุวันที่ปิด ถ้าอยากใส่วันที่ บอกได้เลย ฉันจะสั่งแก้ก่อนอนุมัติ

**เมื่อคุณตอบว่า "อนุมัติ"** ฉันจะรันคำสั่งนี้:
```
python3 team.py approve 20261124-060222-mdhi publish
```
คำสั่งนี้จะสร้างไฟล์อนุมัติ `approve/publish` และบันทึกลงกระดานของ run ว่าอนุมัติแล้ว run ยังรออยู่เบื้องหลังและตั้งให้รอได้ไม่จำกัดเวลา (`--gate-timeout 0`) จึงเห็นไฟล์อนุมัติแล้วไปต่อทันที yolo1 จะสร้างโฟลเดอร์ `/workspace/ex/35/publish/` แล้วคัดลอก `notice.md` ไปไว้ในนั้นโดยไม่แก้เนื้อหา เสร็จแล้วงาน `publish` จะเป็น `ok` และ run ปิดพร้อมตารางสรุป ฉันจะเปิดดูไฟล์ที่คัดลอกแล้วรายงานให้คุณอีกที

ถ้าตอบว่าไม่อนุมัติ ไฟล์จะไม่ถูกคัดลอก และฉันจะหยุด run ให้

## คำตอบของ Claude

ฉันอนุมัติงาน `publish` แล้วรันต่อจนจบ ตอนนี้ทั้ง 3 งานสถานะ `ok` ครบ ใน run `20261124-060222-mdhi`

ระหว่างหยุดรอ run เดิมที่รันอยู่เบื้องหลังถูกหยุดไปเมื่อเซสชันก่อนจบ ฉันจึงสร้างไฟล์อนุมัติด้วยคำสั่ง `approve` แล้วสั่ง `run --resume` แทนการรอให้ run เดิมไปต่อเอง ระบบรันเฉพาะงาน `publish` ส่วน `write` และ `check` ไม่ได้รันซ้ำ

**1. สถานะของทุกงานหลังรันต่อ**

| งาน | สถานะก่อนอนุมัติ | สถานะหลังอนุมัติ |
|---|---|---|
| write (yolo1, haiku/low) | ok: saved | ok: saved (ไม่ได้รันซ้ำ) |
| check (cyolo1, gpt-6.2-sol/low) | ok: ผ่าน | ok: ผ่าน (ไม่ได้รันซ้ำ) |
| publish (yolo1, haiku/low) | waiting_approval | ok: copied (ใช้เวลา 4.9 วินาที) |

**2. ไฟล์ใน publish:** มี `/workspace/ex/35/publish/notice.md` จริง ขนาด 790 ไบต์ ฉันใช้ `cmp` เทียบกับต้นฉบับแล้ว เนื้อหาเหมือนกันทุกไบต์

**คัดลอกกลับมาที่ `./exercises/35` แล้ว:**
- `graph.json`: แผนงาน
- `notice.md` และ `publish/notice.md`: งานจากโฟลเดอร์ ex/35
- `run/`: โฟลเดอร์ของ run ทั้งชุด มีผลแต่ละงานใน `out/`, ไฟล์อนุมัติใน `approve/publish`, `board.md`, `state.json`, `ledger.jsonl` และ log
