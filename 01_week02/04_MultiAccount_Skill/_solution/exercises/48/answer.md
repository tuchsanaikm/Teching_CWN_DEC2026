# แบบฝึกหัดที่ 48 · สร้างสกิลใหม่ที่เรียกใช้ agent-team

ผลจากการรันจริง 1 ครั้ง ผลของแต่ละคนจะต่างกันไปตามบัญชี รุ่น และวันที่รัน

## พรอมต์

```text
สร้างสกิลใหม่ชื่อ poster-team เวอร์ชัน 0 ไว้ที่ ./skills-lab/poster-team ห้ามแตะที่เก็บสกิลกลางใน container multi-account
1. สกิลรับหัวข้อของงานอีเวนต์ แล้วใช้สกิล agent-team ทำ 3 อย่าง คือ ข้อความของโปสเตอร์ ภาพประกอบที่ผ่านการตรวจข้ามค่าย และหน้าเว็บ 1 หน้าที่รวมข้อความกับภาพ
2. เขียนคู่มือของสกิลให้สั้น: ใช้เมื่อไร สั่งอย่างไร ได้ผลอะไร และแผนงานต้นแบบ
3. ทดสอบ 1 ครั้งในโฟลเดอร์ทดลองใน container ด้วยหัวข้อ "งานวิ่งการกุศล 5 กิโลเมตร" งานทุกชิ้นใช้ความยาก 2 แล้วคัดลอกผลกลับมาที่ ./exercises/48
สรุป: โครงสร้างไฟล์ของสกิล · ผลทดสอบ · สิ่งที่ควรปรับในเวอร์ชันถัดไป
```

## คำตอบของ Claude

poster-team เวอร์ชัน 0 สร้างเสร็จแล้ว และรันทดสอบจริง 1 ครั้งจนครบ ได้ข้อความ ภาพ และหน้าเว็บ แต่ภาพไม่ผ่านผู้ตรวจข้ามค่ายทั้ง 3 รอบ ได้ใช้เพราะผู้ตัดสิน (Claude) อนุมัติให้ ส่วนการตรวจหน้าเว็บสุดท้ายได้ "ผ่าน" ครบทุกหัวข้อ

ไม่ได้แก้ไฟล์ในที่เก็บสกิลกลางของ container `multi-account` ใช้แค่อ่านคู่มือ agent-team และรัน `team.py` ของมัน

## โครงสร้างไฟล์ของสกิล
```
skills-lab/poster-team/
├── SKILL.md                         คู่มือสั้น: ใช้เมื่อไร · สั่งอย่างไร · ได้ผลอะไร · ตารางแผนงานต้นแบบ
├── references/graph.template.json   แผนงานต้นแบบ 4 งาน
└── scripts/poster_team.py           แทนหัวข้อและความยากลงในแผน แล้วสั่ง agent-team รัน พร้อมบันทึก run.log
```
แผนงานมี 4 ชิ้น:
- **text** (Claude) เขียนข้อความโปสเตอร์
- **art** (Gemini สร้างภาพ → Codex ตรวจ → Claude ตัดสิน) ทำงานพร้อมกับ text
- **page** (Codex) ทำหน้าเว็บ 1 หน้าที่รวมข้อความกับภาพ หลังสองงานแรกเสร็จ
- **check** (Gemini) เทียบหน้าเว็บกับข้อความ แล้วตอบผ่าน/ไม่ผ่าน

งาน check ผมเพิ่มเองนอกเหนือจาก 3 อย่างที่ขอ ไว้กันหน้าเว็บมีข้อความไม่ตรง

คำสั่งพื้นฐาน: `python3 poster_team.py "หัวข้อ" --out <โฟลเดอร์> [--difficulty 2] [--details ...] [--topic-file ...] [--dry-run]`

## ผลทดสอบ
ทดสอบที่ `/workspace/skills-lab-runs/poster-team-v0/` ใน container ทุกงานใช้ความยาก 2 รหัสการรันคือ `20261124-060023-uqel` จบโดยไม่มีงานล้ม

| งาน | บัญชี | เวลา (วินาที) | โทเค็น เข้า / ออก | ผล |
|---|---|---|---|---|
| text | yolo2 | 13.5 | 6 / 886 | สำเร็จ |
| art | gyolo1/2 สร้าง · cyolo2 ตรวจ · yolo2 ตัดสิน | 326.8 | 223,636 / 8,367 | ไม่ผ่านการตรวจทั้ง 3 รอบ → ผู้ตัดสินอนุมัติ |
| page | cyolo1 | 101.0 | 398,199 / 3,972 | สำเร็จ |
| check | gyolo2 | 18.4 | 14,231 / 1,715 | **ผ่าน** ตรงทั้ง 7 หัวข้อ |

- **ภาพ:** ภาพสุดท้ายเป็นนักวิ่งหลายวัยในสวน มีลูกโป่งหัวใจและโต๊ะแจกน้ำ ไม่มีตัวอักษรในภาพ ผู้ตรวจไม่ผ่านทุกรอบเพราะภาพไม่สื่อว่าระยะ "5 กิโลเมตร" ซึ่งเป็นไปไม่ได้เมื่อเกณฑ์ห้ามมีตัวเลข เกณฑ์ที่ผมเขียนจึงขัดกันเอง ผู้ตัดสินอนุมัติด้วยเหตุผลข้อนี้
- **ข้อมูลที่แต่งขึ้น:** ข้อความโปสเตอร์มีวันที่ สถานที่ เว็บไซต์ และเบอร์โทรที่ AI แต่งขึ้นเอง (เว็บไซต์ลงท้าย `.example`) เพราะการทดสอบไม่ได้ใส่ `--details`
- **หน้าเว็บ:** ตั้งภาษาเป็นไทย รองรับจอมือถือ และเรียกภาพ `art.png` ถูกต้อง

ผลคัดลอกกลับมาที่ `./exercises/48` แล้ว ประกอบด้วย `text.md`, `art.png`, `index.html`, `graph.json`, `run.log`, `summary.md` และ `run-dir/` (ทั้งโฟลเดอร์การรัน รวมภาพทุกรอบและผลตรวจแต่ละรอบ)

## สิ่งที่ควรปรับในเวอร์ชันถัดไป
1. **เกณฑ์ภาพ:** ระบุชัดว่าห้ามบังคับให้ภาพแสดงตัวเลข ระยะทาง หรือวันที่ ให้ตรวจแค่ว่าสื่อประเภทงาน และไม่ให้นับรูปทรงตกแต่งอย่างหัวใจเป็นป้าย จะลดรอบที่เสียไปได้มาก ตอนนี้งานภาพกินเวลาประมาณ 70% ของทั้งหมด
2. **รายงานภาพที่ไม่ผ่าน:** เมื่อภาพไม่ผ่านการตรวจแต่ผู้ตัดสินอนุมัติ ควรเขียนเหตุผลลงสรุปของสกิลให้เห็นชัด ไม่ใช่ซ่อนอยู่ใน run.log
3. **ข้อมูลที่แต่งขึ้น:** เมื่อไม่ได้ใส่ `--details` ควรให้หน้าเว็บแสดงช่อง "รอยืนยัน" หรือติดป้ายว่าเป็นข้อมูลตัวอย่าง แทนการใส่วันที่และเบอร์โทรที่ดูเหมือนจริง
4. **ความยากรายงาน:** ตอนนี้ทุกงานใช้ค่าเดียวกัน ควรตั้งแยกได้ เช่น `--difficulty text=1,page=3`
5. **คัดลอกผลกลับ:** เพิ่มตัวเลือกคัดลอกผลกลับเครื่อง host อัตโนมัติ และเขียน summary.md เอง (รอบนี้ผมทำด้วยมือ)
