# agent-team — ทีม yolo + cyolo + gyolo จากแผนไฟล์เดียว

`A = python <โฟลเดอร์ skills>/agent-team/scripts/agent-team.py` (ในเครื่องนี้คือ `python C:\t\ma04\b\app\skills\agent-team\scripts\agent-team.py`)

| ต้องการอะไร | ใช้คำสั่งไหน |
|---|---|
| ตรวจแผน ดูหัวหน้า และดูว่าใครจะทำอะไร (ไม่เรียกโมเดล) | `A run plan.toml --dry-run` |
| รันทั้งแผนจนจบ | `A run plan.toml` (จำกัดบัญชีด้วย `--accounts yolo2,cyolo1,gyolo`) |
| ดูภาพรวมทีมระหว่างรันหรือหลังรัน | `A team <run-id>` |
| อนุมัติหรือไม่อนุมัติงานที่รออยู่ (แล้วทำต่อทันที) | `A approve <run-id> <task>` · `A reject <run-id> <task>` |
| หัวหน้า (โปรเซส) ตาย ให้คนใหม่อ่านไฟล์แล้วทำต่อ | `A takeover <run-id>` |
| จำลองเหตุการณ์ | `--simulate "quota:yolo2=95@1,fail:gyolo1@2,leader-crash@2"` ตอน run หรือสั่งระหว่างรันด้วย `A simulate <run-id> fail:cyolo1` |
| รันใหม่เฉพาะงานที่ล้ม ถูกหยุด หรือถูกบล็อก (คุณสั่งเอง) | `A resume <run-id> [--plan แผนที่แก้] [--only id1,id2] [--move-held]` |
| ดูสรุปหรือรายการ run | `A report <run-id>` · `A list` |

- **เรียกจากเครื่องของผู้ใช้:** สคริปต์จะ copy ตัวเองพร้อมสกิลทั้ง 3 ตัว แผน และไฟล์ที่แนบเข้า container ให้ แล้วรันที่นั่น เมื่อจบจะ copy โฟลเดอร์ run กลับมาที่ `./team-runs/<run-id>/`
- **ใน container:** ใช้ `python3 agent-team.py ...` ได้เหมือนกัน
- ต้องมี `docker` และ Python 3.11 ขึ้นไปสำหรับแผน TOML

## เขียนแผน
ตัวอย่างเต็มที่ใช้ได้ทันทีอยู่ที่ [examples/example-plan.toml](examples/example-plan.toml) ด้านล่างคือฉบับย่อ:

```toml
[team]
name = "coldbrew"
accounts = ["yolo", "cyolo1", "gyolo"]   # บัญชีที่อนุญาต (ไม่ใส่ = ทุกบัญชี)
leader = "yolo"                          # หัวหน้าทีม: ตัดสินผลแข่ง ตัดสินภาพ ทำงาน who="leader" และเขียนสรุป
quota_limit = 80                         # บัญชีที่ใช้โควตาถึง 80% จะหยุดรับงานใหม่
budgets = { yolo2 = 200000 }             # งบโทเค็นต่อบัญชีใน run นี้ (หรือ budget_tokens = N ให้ทุกบัญชี)
final_summary = true                     # หัวหน้า (คนปัจจุบัน) เขียนสรุปท้าย run จากไฟล์

[[task]]
id = "facts"
who = "gyolo"
prompt = "List 5 short facts about cold brew coffee, one per line."

[[task]]
id = "tagline"
type = "compete"                         # ทุกค่ายตอบ แล้วหัวหน้าเลือกคำตอบที่ดีที่สุดพร้อมเหตุผล
needs = ["facts"]
prompt = "Using these facts:\n{{facts}}\nWrite a 6-word tagline."
criteria = "short, concrete, no clichés"

[[task]]
id = "publish"
needs = ["tagline"]
approve = true                           # หยุดรอจนคุณสั่ง approve
who = "leader"
prompt = "Write the final announcement using {{tagline}}."
```

**ช่องของ `[[task]]`:**

| ช่อง | ความหมาย |
|---|---|
| `id`, `prompt`, `needs` | ชื่องาน, คำสั่ง (`{{id}}` คือผลของงานก่อนหน้า), งานที่ต้องเสร็จก่อน งานที่พร้อมจะเริ่มทันทีและทำพร้อมกัน |
| `who` | `yolo` / `cyolo` / `gyolo` / บัญชีเช่น `yolo2` (**ระบุบัญชีเองจะไม่ถูกย้ายเงียบ ๆ**) / `leader` / ไม่ใส่ (ทีมเลือกให้) |
| `type` | `task` · `review` (วนทำ–ตรวจ ต้องมี `criteria`) · `image` (Codex สร้าง → Gemini ตรวจ → หัวหน้าตัดสิน) · `compete` (แข่งกัน ผู้ตัดสินเลือก 1 คำตอบ) · `debate` (ตอบ → เห็นคำตอบคนอื่นแล้วแก้ `rounds` รอบ → ผู้ตัดสินสังเคราะห์) |
| `kind` | ใช้เลือกคนเมื่อไม่ระบุ `who`: `code` และ `code-review` → Codex · `doc` → Claude · `image-review` → Gemini · `text` → บัญชีที่โควตาเหลือมากสุด |
| `criteria`, `max_rounds`, `reviewer`, `judge`, `generator`, `blind` | เกณฑ์ตรวจ, จำนวนรอบ, ผู้ตรวจ, ผู้ตัดสิน (ค่าเริ่มต้นคือหัวหน้า), ผู้สร้างภาพ (ค่าเริ่มต้นคือ cyolo), ถ้า `blind=true` ผู้ทำจะไม่เห็นเกณฑ์ |
| `contestants`, `rounds` | ผู้เข้าแข่งของ compete/debate (ค่าเริ่มต้น: 1 บัญชีจากทุกค่ายที่พร้อม), จำนวนรอบถกของ debate |
| `approve` | ถ้าเป็น `true` จะหยุดรอการอนุมัติก่อนเริ่มงาน |
| `attach`, `files`, `difficulty`, `model`, `effort`, `timeout` | ภาพที่แนบ, ไฟล์ข้อมูล, ความยาก 1–6 หรือระบุรุ่นเอง, เวลาสูงสุดต่อการเรียก |

`[team]` มีช่องเหล่านี้:

| ช่อง | ความหมาย |
|---|---|
| `name`, `accounts`, `max_parallel`, `difficulty`, `timeout` | ชื่อทีม, บัญชีที่อนุญาต, จำนวนงานพร้อมกัน, ความยากเริ่มต้น, เวลาสูงสุดต่อการเรียก |
| `inline_limit`, `board` | ผลที่ยาวเกินกี่ตัวอักษรจะส่งเป็นไฟล์, เปิดหรือปิดกระดานความรู้ |
| `leader` | ค่ายหรือบัญชีของหัวหน้า (ค่าเริ่มต้น yolo) |
| `quota_limit` | เกณฑ์ % ที่บัญชีจะหยุดรับงานใหม่ (ค่าเริ่มต้น 80) |
| `budget_tokens`, `budgets` | งบโทเค็นต่อบัญชี (ให้ทุกบัญชีเท่ากัน หรือแยกรายบัญชี) |
| `quota_refresh` | อ่านโควตาจริงซ้ำทุกกี่วินาที (ค่าเริ่มต้น 120) |
| `approval_wait` | วินาทีที่รออนุมัติก่อนหยุด run (ค่าเริ่มต้น 0 = หยุดทันที) |
| `final_summary` | ให้หัวหน้าเขียนสรุปท้าย run |

## ทีมดูแลตัวเองอย่างไร
- **โควตาและงบ:**
  - ทีมเช็กโควตาฟรีตอนเริ่ม และเช็กซ้ำทุก `quota_refresh` วินาทีหลังแต่ละการเรียก
  - บัญชีที่ใช้ ≥ `quota_limit` หรือโทเค็นเกินงบจะ "หยุดรับงานใหม่" งานที่กำลังทำจะทำต่อจนจบ งานในคิวของบัญชีนั้นจะถูกย้ายไปคนอื่น
- **ลูกทีมล้ม:**
  - ถ้าบัญชีล้มด้วยปัญหาของบัญชี (auth, ไม่ได้ล็อกอิน, rate limit, CLI ล่ม) **ก่อนเสียโทเค็น** ขั้นนั้นจะถูกย้ายไปบัญชีอื่นของค่ายเดียวกันก่อน ไม่มีจึงข้ามค่าย และบัญชีที่ล้มจะถูกพักไว้
  - งานที่ล้มเพราะตัวงาน หรือล้มหลังเสียโทเค็นแล้ว จะ **ไม่ทำซ้ำ**
  - งานที่ **ระบุบัญชีเอง** จะกลายเป็น `held` แล้วรายงาน ไม่ย้ายเงียบ ๆ จะย้ายได้เมื่อคุณสั่ง `resume --move-held`
- **หัวหน้า:**
  - แผนและความคืบหน้าอยู่ในไฟล์ของ run folder: `state.json`, `handover.md` (อัปเดตทุกครั้งที่งานจบ), `control.json` (อนุมัติและการจำลอง) และ `lease.json` (heartbeat ของโปรเซสหัวหน้า)
  - ถ้าบัญชีหัวหน้าหยุดรับงานหรือล้ม ทีมจะเลือกหัวหน้าใหม่ (ค่ายเดียวกันก่อน) ซึ่งได้คำสั่งให้อ่าน `handover.md` ก่อนทำงาน
  - ถ้าโปรเซสหัวหน้าตาย ให้สั่ง `takeover` หัวหน้าคนใหม่จะทำต่อ: งานที่เสร็จแล้วไม่ถูกทำซ้ำ งานที่ค้างกลางทาง (`interrupted`) เริ่มใหม่ และงานที่ล้มรอคุณ `resume`
- **อนุมัติ:**
  - งาน `approve = true` จะรอ (`waiting_approval`) งานอื่นยังเดินต่อ เมื่อไม่มีอะไรทำแล้ว run จะหยุดด้วย exit code 4
  - รายละเอียดอยู่ใน `approvals/<task>.md`
  - `approve` จะทำต่อทันที `reject` ทำให้งานที่ต้องรองานนั้นกลายเป็น `blocked`
- **จำลองเหตุการณ์:**
  - `quota:ACCT=PCT[@N]`: ตั้งแต่การเรียกครั้งที่ N ของบัญชี โควตาจะอ่านได้ PCT% (N=0 คือทันที)
  - `fail:ACCT[@N]`: บัญชีล้มตั้งแต่การเรียกครั้งที่ N โดยไม่เรียก CLI จริงและไม่เสียโทเค็น
  - `leader-crash@N`: โปรเซสหัวหน้าตายหลังงานเสร็จ N งาน
  - `clear`: ล้างการจำลองทั้งหมด
- **ภาพรวมทีม:** `team` และ `report.md` แสดงตาราง `บัญชี | บทบาท | งานที่ทำอยู่ | โทเค็นที่ใช้ | โควตา | สถานะ` พร้อมประวัติการย้ายงาน การหยุดรับงาน การล้ม และการเปลี่ยนหัวหน้า

**ผลลัพธ์ของ run:**
- ตาราง `งาน | บัญชี | รุ่น | เวลา | โทเค็น | สถานะ`, ภาพรวมทีม, ขั้นตอนย่อย, โควตาหลังจบงาน และ audit
- exit code: `0` สำเร็จ · `1` มีงานไม่สำเร็จ · `2` แผนผิด (ไม่มีการเรียกใด ๆ) · `3` ไม่มีบัญชีพร้อม · `4` หยุดรออนุมัติ · `9` โปรเซสหัวหน้าตาย (จำลอง) ให้ใช้ `takeover`

## กฎ (สคริปต์บังคับให้แล้ว)
- **ไม่รันผลลัพธ์ของ AI เป็นคำสั่ง:** ผลถูกวางลงใน prompt เป็นข้อมูลเท่านั้น และ VERDICT, DECISION, WINNER อ่านด้วย regex
- **ไม่ทำซ้ำงานที่เสียโทเค็นไปแล้ว:** การย้ายบัญชีเกิดเฉพาะเมื่อบัญชีล้มโดยยังไม่เสียโทเค็น
- **บัญชีที่อนุญาต:**
  - สกิลย่อยทุกตัวรันด้วย `AI_SKILL_ACCOUNTS=<บัญชีเดียว>`
  - หลักฐานอยู่ใน `audit.log`
  - ถ้าแผนอ้างบัญชีนอกรายการ จะได้ `PLAN ERROR` ก่อนเรียกอะไรทั้งหมด
  - `resume --plan` ที่ task id ไม่ตรงกับ run จะถูกปฏิเสธ
- **ห้ามเปิดไฟล์ credential และห้ามล็อกอินแทนผู้ใช้**

## ข้อควรรู้
- ตอนนี้ gyolo สร้างภาพไม่ได้ (image model ตอบ 503) ให้ใช้ผู้สร้างภาพค่าเริ่มต้น (cyolo)
- cyolo1 กับ cyolo2 เป็นการล็อกอินเดียวกัน
- การจำลองเก็บอยู่ใน `control.json` ของ run และยังมีผลต่อเมื่อ `resume` หรือ `takeover` ถ้าไม่ต้องการแล้วให้สั่ง `simulate <run-id> clear` ก่อน
