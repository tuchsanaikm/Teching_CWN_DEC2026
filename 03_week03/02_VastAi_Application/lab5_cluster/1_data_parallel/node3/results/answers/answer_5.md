## สรุปผล LAB 5 — Data Parallelism บนคลัสเตอร์ 3 Node (6 × RTX 3090)

### สิ่งที่ควรรู้

- **GPU ว่างเกือบตลอด:** GPU util เฉลี่ยเพียง 6–7% เพราะแต่ละ step คำนวณ 0.36 s แล้วรอเครือข่ายอีก 4–5 s (Node อยู่คนละที่ RTT ประมาณ 75–80 ms)
- **เครือข่ายสะดุดระหว่างเทรน:** ช่วง step 157 เครือข่ายเข้า Node 1 ค้างประมาณ 2 นาที และช่วงต้น Epoch 2 ลิงก์ไป Node 3 ช้าลงเป็น 8–12 s/step งานเดินต่อเองได้โดยไม่ต้องต่อใหม่ ค่าเฉลี่ย 5.34 s จึงสูงกว่ามัธยฐาน 3.99 s
- **ทดสอบ 3 step:** ใช้ batch ยาว 256 / 63 / 104 / 64 token (padding ถึง 256) ผ่านโดยไม่ Out of Memory ใช้ VRAM สูงสุด 21,864 MB จาก 24,124 MB โค้ดคำนวณ lm_head เฉพาะตำแหน่งคำตอบตั้งแต่แรกเพื่อประหยัดหน่วยความจำ ค่าที่ตรึงไม่ถูกแตะ
- **บั๊กที่เจอและแก้ในรอบทดสอบ:** รอบแรกช้า 16 s/step เพราะตั้งขนาด buffer ของ socket เอง เอาออกแล้วเหลือประมาณ 4 s/step
- **Base ได้ Exact Match ต่ำ:** ส่วนใหญ่เพราะ Base ใช้ `'...'` และตัวพิมพ์ใหญ่ต่างจากเฉลย ไม่ใช่เพราะ `;` ท้ายคำสั่ง (ตัดออกก่อนเทียบแล้ว)
- **การตรวจน้ำหนักเท่ากัน:** โปรแกรมกลางเทียบ sha256 จากทั้ง 6 ตัว และผมคำนวณ sha256 ซ้ำจากไฟล์ checkpoint บนทั้ง 3 Node ได้ค่าตรงกัน
- **สิ่งที่ผมเลือกเอง (โจทย์ไม่ได้กำหนด):** ใช้ AdamW แบบ learning rate คงที่ ไม่มี weight decay, เขียน LoRA เองแทน peft (บนเครื่องไม่มี peft), ตั้ง system prompt เอง และเฉลี่ย Gradient แบบถ่วงตามจำนวนตัวอย่าง ถ้า LAB 4.2 ใช้ค่าต่างจากนี้ ตัวเลขจะเทียบกันตรง ๆ ไม่ได้
- **ยังไม่ได้ทดสอบ:** การต่อใหม่อัตโนมัติเมื่อการเชื่อมต่อหลุด และ `--resume_epoch` เขียนไว้แล้วแต่ไม่ได้ถูกใช้จริงในรอบนี้ (ไม่มีการหลุด) ส่วนการรันใน tmux ให้ทนต่อ SSH หลุดนั้นใช้จริงตลอดการเทรน
