### สิ่งที่เกิดระหว่างทำ
- **ลอง 3 step:** แบบคำนวณ logits ทุกตำแหน่ง Out of Memory บน GPU ที่ได้ batch กว้าง 256 token จึงแก้ `worker.py` ให้คำนวณ logits เฉพาะตำแหน่งคำตอบ SQL (loss เท่าเดิม) แล้วผ่านที่ VRAM สูงสุด 22,063 MiB โดยไม่เปลี่ยนค่าที่ตรึง
- **เน็ตสะดุด 2 ช่วง:** ขาขึ้น Node 2 → Node 1 ช้าลงมาก ทำให้ 16 step ใช้ 6–44 s (รวม 462 s) ถ้าไม่นับ 16 step นี้เฉลี่ย 2.72 s/step การเชื่อมต่อไม่หลุดและไม่มี reconnect
- **การแบ่งข้อมูล:** แต่ละ Epoch เห็นครบ 4,000 ตัวอย่างไม่ซ้ำ และไม่มี step ใดที่โปรแกรมเทรนได้ตัวอย่างซ้ำกัน
- **การรันต่อเมื่อหลุด:** ทุกอย่างรันใน tmux บนเครื่อง ทดสอบปิดโปรแกรมกลางกลางทางแล้วเปิดใหม่ โปรแกรมเทรนต่อกลับเองและรันครบ 12 step น้ำหนักเท่ากัน ส่วนการ resume จาก checkpoint (บันทึกทุก 50 step) เขียนไว้แต่ยังไม่ได้ทดสอบ
- **Base ได้ 1.5%:** เพราะวัดแบบเข้มงวด ตัดแค่ช่องว่างซ้ำและ `;` ท้ายคำสั่ง Base มักตอบด้วย `'...'` และตัวพิมพ์ต่างจากเฉลย จึงนับเป็นผิด

### ค่าที่เลือกเอง (โจทย์ไม่ได้ตรึง)
- AdamW, weight decay 0, learning rate คงที่, LoRA dropout 0
- น้ำหนัก LoRA และ Gradient เป็น float32 ส่งแบบไม่บีบอัด (โมเดลฐานเป็น bf16)
- มี 1 ตัวอย่างใน Training Set ที่ยาวเกิน 256 token และถูกตัดท้าย
