## สรุปผล Lab 5 · Model Parallel 3 Node

งานครบทั้ง 4 ขั้น: ดึงผลดิบกลับมาแล้ว เขียน `code/report.py` ได้ `metrics.json` กับกราฟ 4 รูป และลบเครื่องทั้ง 3 Node แล้ว ตรวจซ้ำไม่เหลือเครื่องใดในบัญชี

### ผลการเทรน (Qwen3-8B + LoRA, text-to-SQL, 2 Epoch, 334 step, batch 8 ต่อ Node)

| ตัวชี้วัด | ค่า |
|---|---|
| ตัวอย่างต่อวินาที | **4.32** (8,000 ตัวอย่างใน 1,851.9 วินาที) |
| สัดส่วนเวลาที่ใช้ส่งและรอ | **86.8%** ของเวลาต่อ step |
| Exact Match (200 ข้อ) | Base 1.5% → Epoch 1 **69.0%** → Epoch 2 **71.0%** |
| เงินต่อ 1,000 ตัวอย่าง | **$0.0855** (ราคา 3 เครื่องรวม $1.33/ชม.) |

| รายการ | Node 1 | Node 2 | Node 3 |
|---|---|---|---|
| วินาทีต่อ step (เฉลี่ย) | 5.51 | 5.53 | 5.53 |
| เวลาคำนวณบน GPU (วินาที) | 0.77 | 0.70 | 0.72 |
| เวลาส่งและรอ (วินาที) | 4.74 | 4.82 | 4.81 |
| สัดส่วนส่งและรอ | 86.0% | 87.3% | 87.0% |
| GPU util เฉลี่ย GPU 0 / GPU 1 | 7.3% / 6.6% | 6.2% / 6.3% | 6.9% / 6.1% |

- **คอขวดคือเครือข่าย:** GPU ทำงานเฉลี่ยเพียง 6.6% เพราะแต่ละ step ต้องส่ง Gradient 15.3 MB ข้ามเครื่อง (อาร์เจนตินา–ชิลี) แล้วรอค่าเฉลี่ยกลับมา
- **loss:** step แรก 2.02 → เฉลี่ย Epoch 1 0.1516 → เฉลี่ย Epoch 2 0.0426 ส่วน test loss คือ 1.9154 → 0.0655 → 0.0588
- **Epoch 2 ช่วยได้น้อย:** Exact Match เพิ่มเพียง 2 จุด (138 → 142 ข้อ)

### การลบเครื่อง
ลบ <id>, <id> และ <id> โดยตรวจป้ายตรงกับ ID ก่อนลบ ขณะนั้นบัญชีมีเพียง 3 เครื่องนี้ จึงไม่ได้แตะเครื่องป้ายอื่น ก่อนลบได้ตรวจ sha256 ของผลดิบทุกไฟล์ว่าตรงกับบนเครื่อง ไม่มีค่า key หรือ token ถูกแสดงหรือบันทึกลงไฟล์
