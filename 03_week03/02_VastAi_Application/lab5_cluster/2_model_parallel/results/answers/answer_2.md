# สรุป LAB 5.2 — Model Parallelism บนคลัสเตอร์ 2 Node (Qwen3-8B → SQL)

เทรนครบ 2 Epoch (500 step) และวัดผลครบ Exact Match ขึ้นจาก 1.5% (Base) เป็น 74.0% หลัง Epoch 2 และน้ำหนัก LoRA ของ 2 Node เท่ากันทุกบิตหลังจบทั้ง 2 Epoch ระหว่างทางมีสะดุด 2 ครั้ง (รันแรกต้องยกเลิก และ host ของ Node 1 reboot เอง) รายละเอียดอยู่ด้านล่าง

**เครื่องทั้ง 2 ยังเปิดอยู่** (`vapp-lab5-mp-1` และ `vapp-lab5-mp-2` สถานะ running, GPU ว่าง, ไม่มีโปรแกรมค้าง) — ยังคิดเงินอยู่ประมาณ $0.91/ชม. รวมกัน

- **Exact Match:** เทียบข้อความหลังยุบช่องว่างและตัด `;` ท้ายคำสั่ง โดยยังแยกตัวพิมพ์เล็กใหญ่
- **Base ได้ต่ำ:** ตอบด้วย `'...'` ถึง 190/200 ข้อ ขณะที่เฉลยใช้ `"..."`
- **GPU util ต่ำ:** เวลาส่วนใหญ่ของ step คือการส่งและรอข้ามประเทศ (ฝรั่งเศส–เช็ก) Node 2 มาถึงทีหลังทุก step
- **เวลาส่งแกว่งตามเครือข่าย:** step 0–149 เฉลี่ย 3.28 s ส่วน step 150–499 เฉลี่ย 2.24 s

## สิ่งที่เกิดระหว่างรัน

1. **ลอง 3 step ไม่ Out of Memory** — batch ยาวสุด 256 token ปนสั้น ใช้สูงสุดราว 14.3 / 14.8 GB ต่อใบ โค้ดคำนวณ lm_head เฉพาะตำแหน่งคำตอบตั้งแต่แรก จึงไม่ต้องแก้เพิ่ม ตัวอย่าง 256 token มีตัวเดียวและอยู่ในครึ่งของ Node 1 ดังนั้น batch ทดสอบของ Node 2 ยาวสุด 206 token
2. **รันแรกถูกยกเลิกที่ ~step 117** — ใช้ 1 connection ต่อ Node แล้วการส่งค้าง บาง step รอ 92 วินาที ผมเขียนการส่งใหม่เป็น 4 connection ต่อ Node เข้า port เดียวกัน และตัดแล้วต่อใหม่เมื่อข้อมูลไม่ไหล 8 วินาที จากนั้นเริ่มเทรนใหม่จาก step 0
3. **Host ของ Node 1 หลุดแล้ว reboot เองกลางรันจริง** (~step 162–168 ดับราว 5 นาที) — ทั้งสอง Node ต่อจาก checkpoint step 150 ได้ แต่ผมต้องสั่งเองด้วยมือ: เปิดโปรแกรมกลางกับ worker ของ Node 1 ใหม่ และ kill worker ของ Node 2 ให้ย้อนไป step 150 ระบบยังไม่ย้อนให้เองในกรณีนี้ step ที่คำนวณซ้ำได้ loss เท่าเดิม และสถิติเวลาไม่นับช่วงเครื่องดับ
4. **ทดสอบ kill worker กลางทาง** — worker เปิดใหม่เองและต่อจาก checkpoint น้ำหนักที่ step 10 ตรงกันทั้ง 2 Node

## ค่าที่ผมเลือกเอง

- **ค่าที่โจทย์ไม่ได้กำหนด:** AdamW, weight decay 0, learning rate คงที่, ไม่มี dropout, loss คิดเฉพาะ token ของคำตอบ SQL ถ้า LAB 4.3 ใช้ค่าต่างจากนี้ การเทียบกับผล 1 Node จะไม่ตรงกันพอดี
- **Gradient ขาขึ้นส่งเป็น bf16 แทน float32:** ขนาดลดครึ่งหนึ่ง และโค้ดตรวจทุก step ว่าค่าไม่เปลี่ยน (ครบ 500/500 step)
- **eval รันหลังเทรนจบ** ไม่ได้รันคั่นระหว่าง Epoch เพื่อไม่ให้รบกวนการจับเวลา โดยใช้ LoRA ที่บันทึกไว้ตอนจบแต่ละ Epoch
