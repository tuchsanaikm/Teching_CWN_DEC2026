ผู้ใช้แชทบอทรู้สึกช้าได้ 2 แบบ จึงต้องวัด 3 ตัวชี้วัดคู่กันเสมอ

1TTFT (Time To First Token): เวลาตั้งแต่ส่งคำถามจนได้ Token แรก ถ้านานผู้ใช้รู้สึกว่าบอทค้าง
2ความเร็วต่อผู้ใช้ (tok/s): ความเร็วการไหลของข้อความหลัง Token แรก วัดที่ p5 (95% ของผู้ใช้ต้องเร็วกว่าค่านี้)
3System Throughput (tok/s): ผลรวม Token ต่อวินาทีของทุกคน บอกความคุ้มค่าของ GPU
ตัวชี้วัดและเกณฑ์ SLO

ผู้ใช้มากขึ้น System Throughput สูงขึ้น แต่ความเร็วต่อผู้ใช้แต่ละคนจะลดลง

1ผู้ใช้ 1 คน ได้ความเร็วสูงสุด (104.9 tok/s) แต่ GPU ทำงานไม่เต็ม Throughput จึงต่ำ
2ผู้ใช้หลายคนพร้อมกัน GPU ผลิต Token รวมได้สูงขึ้นมาก แต่ต้องแบ่งแบนด์วิดท์กัน ทำให้แต่ละคนช้าลง
3Speed Retention = ความเร็วที่ N คน ÷ ความเร็วผู้ใช้ 1 คน บอกว่ายังรักษาความเร็วเดิมไว้ได้กี่ส่วน
ตัวชี้วัดและเกณฑ์ SLO

เกณฑ์ SLO มี 2 ระดับ (Standard และ Fast) และความจุต้องระบุคู่กับระดับเสมอ

1Standard SLO: TTFT p95 ≤ 2.0 วินาที, ความเร็ว p5 ≥ 15.0 tok/s, error < 1% (เร็วกว่าคนอ่านทัน)
2Fast SLO: TTFT p95 ≤ 2.0 วินาที, ความเร็ว p5 ≥ 50% ของผู้ใช้ 1 คน (52.44 tok/s บน dp2 · 50.07 tok/s บน mp4), error < 1%
3ความจุ (Capacity) = จำนวนผู้ใช้พร้อมกัน (N) สูงสุดที่ยังผ่านเกณฑ์ของระดับนั้น

มี GPU หลายใบแบ่งงานแบบไหน: หุ่นยนต์เต็มตัว (Data Parallelism) vs แบ่งครึ่ง (Model Parallelism)แนวคิดหลัก · หลาย GPU

1Data Parallelism (สัญลักษณ์: หุ่นยนต์เต็มตัวใบละ 1 ตัว): แต่ละ GPU ถือโมเดลครบทั้งก้อน แยกกันตอบคำถามคนละข้อ ไม่ต้องคุยข้ามการ์ดจอ เหมาะเมื่อโมเดลใส่ใน 1 GPU พอและต้องการรับคำขอพร้อมกันจำนวนมาก
2Model Parallelism (สัญลักษณ์: หุ่นยนต์ 1 ตัวแบ่งลง 2 ใบ): จับคู่ GPU 2 ใบช่วยกันถือ 1 โมเดลเพื่อรวม VRAM สำหรับโมเดลขนาดใหญ่ หรือช่วยกันคำนวณเพื่อลดเวลาตอบต่อคำขอเดียว
3ราคาที่ต้องแลก (ต้องวัดเทียบจริง): ในแบบ Tensor Parallelism ทั้ง 2 GPU ต้องสื่อสารผลข้าม PCIe ระหว่างกันตลอดการสร้าง Token ซึ่งเราจะวัดเทียบจริงในขั้นที่ 8
