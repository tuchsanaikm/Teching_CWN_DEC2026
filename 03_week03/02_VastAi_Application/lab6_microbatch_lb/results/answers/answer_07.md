### ผู้ใช้คนเดียว (N=1)

แบบที่ 2 ช้ากว่าแบบที่ 1 **ประมาณ 5 ms** (p50 30.0 เทียบ 24.9 ms = +5.1 ms; p95 36.2 เทียบ 31.0 ms = +5.2 ms) สาเหตุคือช่วงรอรวมรูป 5 ms: เวลารอในคิวขึ้นจาก 0.07 เป็น 5.17 ms ขณะที่เวลาโมเดลแทบเท่าเดิม (16.6 เทียบ 16.9 ms) เพราะมีรูปเดียว รอไปก็ไม่มีรูปอื่นมารวม

### ตัวถ่วงของแบบที่ 2

ตัวถ่วงคือ **งาน CPU ใน worker thread ตัวเดียวของ server ไม่ใช่ GPU** (GPU ใช้แค่ราว 32% แม้ batch เต็ม 32)

- **เวลาโมเดลโตตามจำนวนรูปเกือบเป็นเส้นตรง:** 16.9 ms ที่ 1 รูป เป็น 217 ms ที่ 32 รูป คือราว 6.8 ms ต่อรูป Throughput จึงตันที่ราว 130–143 รูป/วินาทีตั้งแต่ N=16
- **แยกส่วนของการเรียกโมเดล 1 ครั้งที่ 32 รูป** (วัดบน GPU ใบที่ว่าง รวม 134 ms): เตรียมรูป 44 ms + หลังประมวลผล/NMS 30 ms = 55% เป็นงาน CPU ที่ทำทีละรูป ส่วน inference 59 ms
- **ใน server จริงช้ากว่านั้นอีก** (217 เทียบ 134 ms) น่าจะเพราะ thread โมเดลแย่ง GIL กับ thread ที่รับคำขอ ถอดรหัส JPEG และสร้าง JSON ข้อนี้เป็นข้อสันนิษฐาน ยังไม่ได้วัดยืนยัน
- **batch เฉลี่ยได้แค่ราว N/2:** ผู้ใช้ครึ่งหนึ่งส่งรูปเข้ามาระหว่างที่โมเดลกำลังทำ batch ก่อนหน้า ทุกรูปจึงรอคิวราวหนึ่งรอบโมเดลแล้วค่อยเข้าโมเดลอีกหนึ่งรอบ
