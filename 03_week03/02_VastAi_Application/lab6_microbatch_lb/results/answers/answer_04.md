## สรุปงาน: ตัวยิงโหลด `code/loadgen.py`

เขียน `loadgen.py` เสร็จและลองยิงระบบแบบที่ 1 (1 GPU, 1 server, โหมด single) ด้วย N = 4 แล้ว ใช้งานได้ ผ่านเกณฑ์ โหมดหาความจุลองรันจริงเฉพาะแบบย่อ (ระดับละ 6 วินาที) เพื่อตรวจว่าทำงานครบ 3 จังหวะ ยังไม่ได้วัดความจุจริงแบบระดับละ 20 วินาที

### อธิบายโค้ด
1. **ผู้ใช้จำลอง** – แต่ละคนถือ connection ของตัวเอง ส่งรูปเข้า `127.0.0.1:8080/v1/detect` รอคำตอบแล้วส่งรูปถัดไปทันที วน 6 รูป เกิน 10 วินาทีหรือไม่ใช่ HTTP 200 นับเป็น error
2. **การวัด 1 ระดับ** – ยิง 20 วินาที ตัด 5 วินาทีแรกทิ้ง ระหว่างนั้นเก็บ GPU % ทุกใบและ CPU ของ server / NGINX / ตัวยิงโหลดทุก 0.5 วินาที แล้วสรุปค่าตามข้อ 4 ครบทุกตัว
3. **วิธีนับ** – p50/p95/p99 และ error นับจากคำขอที่ "เริ่มส่ง" ในช่วงวัดและตามจนจบ ส่วน Throughput นับคำตอบสำเร็จที่ "มาถึง" ในช่วงวัด หารด้วย 15 วินาที
4. **โหมด `capacity`** – หาช่วง → ประมาณด้วยเส้นตรง → ปรับจนห่างไม่เกิน 2 คน (N เกิน 100 ใช้ 4 คน) พร้อมพิมพ์ค่าเทียบ N ≈ Throughput สูงสุด × 0.5 วินาที
5. **โหมด `single` และผลลัพธ์** – ยิง N ค่าเดียว บันทึกรายวินาที ทั้งสองโหมดบันทึกเป็น `results/<name>.json` พิมพ์ผลทีละระดับ จบด้วยบรรทัด `CAPACITY: ...` และ `DONE`

สิ่งที่ผมเลือกเองนอกเหนือจากโจทย์:
- การวัดซ้ำระดับที่ไม่ผ่าน ใช้กับทุกจังหวะ ไม่เฉพาะตอนหาช่วง
- ถ้าเส้นตรงขยับปลายเดิมซ้ำ 2 รอบ รอบถัดไปใช้จุดกึ่งกลางแทน เพื่อไม่ให้การปรับค้าง
- ระหว่างระดับ รอให้คิวของ server ว่างก่อนยิงระดับถัดไป
- ชื่อผลซ้ำจะไม่เขียนทับ ต้องใส่ `--overwrite`

### แผนภาพผู้ใช้จำลอง 1 คน
```
 ผู้ใช้จำลอง #k                   NGINX :8080                 server (GPU)
      │  เริ่ม (เหลื่อมกันภายใน 1 วินาทีแรก)
      │── POST รูปที่ 1 ──────────────►│── ส่งต่อ (Round Robin) ──►│ เข้าคิว → โมเดล
      │        จับเวลา ⏱ (รอได้ไม่เกิน 10 วินาที)                    │
      │◄── 200 + server, queue_ms, model_ms, batch_size ───────────│
      │  บันทึก: เวลารอ, สำเร็จ/error, server ที่ตอบ
      │── POST รูปที่ 2 ทันที ────────►│ ...
      │        ... รูป 3 → 4 → 5 → 6 → กลับไปรูป 1 ...
      │  ✗ เกิน 10 วินาที / ไม่ใช่ 200 → นับ error ปิด connection แล้วส่งรูปถัดไป
      ▼  ครบเวลา → หยุดส่งใหม่ รอคำขอที่ค้างให้จบ → ส่งบันทึกกลับไปสรุปผล
```

### ผลการลองยิง N = 4 (ระบบแบบที่ 1, 20 วินาที, อุ่นเครื่อง 5 วินาที)
คำสั่ง: `python code/loadgen.py single --name try_n4 --users 4 --duration 20`

| รายการ | ค่า |
|---|---|
| ผลตัดสิน | **ผ่าน** |
| Throughput | 59.9 คำขอ/วินาที |
| เวลารอ p50 / p95 / p99 | 65.0 / 80.6 / 88.6 ms |
| error | 0 จาก 899 คำขอ (0%) |
| GPU | ใบที่ 0 = 21%, ใบที่ 1 = 0% |
| CPU (100% = 1 core) | server 131.9%, NGINX 2.1%, ตัวยิงโหลด 2.8% |
| คำขอที่ server ตอบ | gpu0-8101 = 899 (ทั้งหมด) |
| เวลารอคิว / เวลาโมเดล (เฉลี่ย) | 41.05 ms / 16.31 ms |
| รูปเฉลี่ยต่อการเรียกโมเดล 1 ครั้ง | 1.0 |

GPU ใช้เพียง 21% ขณะที่ server ใช้ CPU เกิน 1 core เวลารอส่วนใหญ่คือเวลารอคิว

### ผลการรันย่อของโหมดหาความจุ (ไม่ใช่ค่าความจุจริง)
รันด้วย `--level-seconds 6 --warmup 2` รวม 13 รอบวัด:
- **หาช่วง:** N = 1–16 ผ่าน, N = 32 และ 64 ไม่ผ่าน (วัดซ้ำแล้วทั้งคู่)
- **ประมาณ/ปรับ:** วัดที่ N = 27 ผ่าน → 30 ไม่ผ่าน → 29 ผ่าน
- **ผลที่พิมพ์:** `CAPACITY: 29 users (N=29 passes, N=30 fails)` ค่าเทียบ 63.2 คำขอ/วินาที × 0.5 = N ≈ 31.6 แล้วพิมพ์ `DONE`

ค่าจริงต้องรัน `python code/loadgen.py capacity --name <ชื่อ>` ด้วยค่าเริ่มต้น 20 วินาที
