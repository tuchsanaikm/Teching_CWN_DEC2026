## สรุปผล แบบที่ 1 (GPU 1 ใบ · server 1 ตัว · ทีละรูป) — ชื่อผล `base`

**แบบที่ 1 รับผู้ใช้พร้อมกันได้ 29 คน** (N=29 ผ่าน, N=30 ไม่ผ่าน) แต่ N=29 อยู่ติดเส้นพอดี: รอบแรกได้ p95 507.4 ms (ไม่ผ่าน) วัดซ้ำได้ 494.4 ms (ผ่าน) ตามกติกาของตัวยิงโหลดที่ให้ตกเฉพาะเมื่อไม่ผ่านทั้งสองรอบ

ระบบเปิดด้วย `cluster.sh up --gpus 1 --per-gpu 1 --mode single` สถานะ OK แล้วรัน `loadgen.py capacity --name base` เป็นงานเบื้องหลังจนเห็น `DONE` (13 รอบวัด รอบละ 20 วินาที นับ 15 วินาทีหลัง) ไม่มี error เลยทุกระดับ

### ตอนเต็มความจุ
- **GPU ทำงานแค่ประมาณ 22%** ที่ N=29 คือยังว่างอยู่ราว 78%
- **ตัวถ่วงคือการเรียกโมเดลทีละรูปใน server ตัวเดียว** แต่ละรูปใช้ประมาณ 16 ms จึงทำได้สูงสุดราว 62 รูป/วินาที และค่านี้ตันตั้งแต่ N=2
- ผู้ใช้ที่เพิ่มขึ้นไม่ได้เพิ่ม throughput แต่ไปต่อคิว: ที่ N=29 เวลารอคิว 437 ms จากเวลาตอบ p50 459 ms
- CPU ของ server ค้างที่ประมาณ 135% ตั้งแต่ N=2 ส่วน NGINX ใช้ประมาณ 2% และตัวยิงโหลดประมาณ 3% จึงไม่ใช่ตัวถ่วง
- ผมไม่ได้วัดแยกว่า 16 ms นั้นเป็นงานฝั่ง CPU เท่าไรและ GPU เท่าไร แต่ GPU ที่ว่างมากบ่งว่าคอขวดอยู่ฝั่ง CPU ของ thread ที่เรียกโมเดล
