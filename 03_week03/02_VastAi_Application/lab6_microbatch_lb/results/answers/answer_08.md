## สรุปผล: แบบที่ 3 (GPU 1 ใบ · server 4 ตัว · Micro-batching) รับได้ 90 ผู้ใช้พร้อมกัน

เปิดระบบใหม่บน GPU 0 ด้วย server 4 ตัว (พอร์ต 8101–8104) โหมด Micro-batching ไม่เกิน 32 รูป รอไม่เกิน 5 ms และ NGINX แจกงานแบบ Round Robin ตัวยิงโหลดชื่อผล `multi` รันเบื้องหลังจนเห็น `DONE` โดย N=90 ผ่าน (p95 468.4 ms) และ N=91 ไม่ผ่านทั้งสองรอบ (537.2 และ 513.3 ms)

| แบบ | ความจุ (N) | Throughput สูงสุด | p95 ที่ความจุ | รูปเฉลี่ยต่อการเรียกโมเดล | GPU ทำงาน | CPU ของ server | VRAM ที่ใช้ | เท่าของแบบที่ 1 |
|---|---|---|---|---|---|---|---|---|
| 1. ทีละรูป (server 1 ตัว) | 29 | 62.6 req/s (N=29) | 494.4 ms | 1.0 | 22% | 136% | 522 MiB | 1.00 |
| 2. Micro-batching (server 1 ตัว) | 52 | 142.9 req/s (N=64) | 490.0 ms | 26.0 | 31% | 181% | 13,812 MiB | 1.79 |
| 3. Micro-batching + server 4 ตัว | 90 | 278.7 req/s (N=128) | 468.4 ms | 11.0 | 82% | 535% (รวม 4 ตัว) | 14,001–14,017 MiB | 3.10 |

- **ที่มาของตัวเลข:** GPU % และ CPU % มาจากรอบที่ผ่านที่ระดับความจุ (CPU 100% = 1 core)
- **VRAM:** แบบที่ 1–2 อ่านหลังเปิดระบบ ส่วนแบบที่ 3 เป็นค่าต่ำสุด–สูงสุดตลอดการวัด (แต่ละ server ใช้ราว 3.1–4.1 GB)
- **Throughput:** แบบที่ 3 ได้ 4.45 เท่าของแบบที่ 1 และค้างอยู่ราว 260–279 req/s ตั้งแต่ N=32 ขึ้นไป

### คำขอกระจายไป server 4 ตัวเท่ากันไหม
- **ที่ความจุ (N=90) เท่ากัน:** 1007 / 1007 / 1008 / 1008 คำขอ คือ 25.0% ต่อตัว และเกือบทุกระดับต่างกันไม่เกิน 1 คำขอ
- **มี 2 รอบที่ไม่เท่า** ทั้งคู่เป็นระดับที่ไม่ผ่านและอยู่สูงกว่าความจุมาก จึงไม่กระทบค่า 90:
  - N=128 รอบที่ 2: 8101 ได้ 441 คำขอ ตัวอื่นได้ราว 1158
  - N=256 รอบที่ 1: 8103 ได้ 278 คำขอ ตัวอื่นได้ราว 1215 และมี HTTP 502 จำนวน 3 ครั้ง (0.08%)
- **สาเหตุ:** log ของ NGINX แสดงว่า server ตัดการเชื่อมต่อ (connection reset) แล้ว NGINX พัก server ตัวนั้นออกจากวงชั่วคราว ผมยังไม่ได้แก้ค่านี้ เพราะอยู่นอกโจทย์

### ตัวถ่วงของแต่ละแบบ
- **แบบที่ 1 — ตัวถ่วงคือการเรียกโมเดลทีละรูปใน server ตัวเดียว:** เรียกครั้งละ ~15.6 ms จึงตันที่ ~63 req/s ขณะที่ GPU ทำงานแค่ 22% เวลาส่วนใหญ่ของคำขอคือรอคิว (~437 ms)
- **แบบที่ 2 — ตัวถ่วงคืองานฝั่ง CPU ใน server ตัวเดียว:** GPU ยังทำงานแค่ 31% ผลจับเวลาแยกส่วนก่อนหน้า (batch 32) แสดงว่าการเตรียมรูปและแปลงผลกินเวลาราว 56% ของการเรียกโมเดล
- **แบบที่ 3 — ตัวถ่วงย้ายมาที่ GPU ใบเดียวที่ 4 server แย่งกันใช้:** GPU ขึ้นเป็น ~82% และการเรียกโมเดลช้าลง (batch ~11 รูปใช้ ~147 ms เทียบกับ ~35–68 ms สำหรับ batch 8–16 ตอนใช้ GPU ลำพัง) ข้อนี้เป็นการตีความจากตัวเลข ไม่ได้ทดลองแยกยืนยัน
