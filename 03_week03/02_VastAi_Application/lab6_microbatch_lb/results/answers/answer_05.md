ตัวยิงโหลด (`loadgen.py`) ผ่านครบทั้ง 5 ทดสอบตั้งแต่รอบแรก จึงไม่มีข้อไหนต้องแก้แล้วทดสอบซ้ำ

| ทดสอบ | ค่าที่ควรได้ | ค่าที่วัดได้ | ผล |
|---|---|---|---|
| **A** ตัวเลขตรงกับที่คำนวณ (รอ 50 ms ยิงตรง) | p50 50 ms และ Throughput 20 / 200 / 1,000 / 2,000 คำขอต่อวินาที ที่ N = 1 / 10 / 50 / 100 (ต่างไม่เกิน 10%) | p50 50.6 ms ทุกระดับ (+1.2%) · Throughput 19.8 / 197.3 / 986.6 / 1,971.3 (−1.0% ถึง −1.4%) | ผ่าน |
| **B** นับครบ | จำนวนที่ส่ง (รวมช่วงอุ่นเครื่อง) เท่ากับที่ server จำลองนับ ต่างไม่เกิน 1% | ตรงกันทุกรอบทั้ง 7 รอบ รวมส่ง 1,386,504 นับได้ 1,386,504 (ต่าง 0%) | ผ่าน |
| **C** ตัวยิงโหลดเร็วพอ (ตอบทันที N = 200) | มากกว่า 2,000 คำขอต่อวินาที | 64,168 คำขอต่อวินาที | ผ่าน |
| **D** NGINX ถ่วงไหม (รอ 50 ms, N = 50) | p50 ช้ากว่ายิงตรงไม่เกิน 10 ms | ยิงตรง 50.6 ms · ผ่านพอร์ต 8080 50.9 ms (ช้ากว่า 0.3 ms) | ผ่าน |
| **E** วัดซ้ำได้ผลเดิม (API จริง แบบที่ 1, N = 8, 3 ครั้ง) | ทั้ง 3 ครั้งต่างกันไม่เกิน 10% | Throughput 57.5 / 58.8 / 60.9 คำขอต่อวินาที (ต่าง 5.8%) · p50 134.0 / 129.8 / 130.9 ms (ต่าง 3.2%) | ผ่าน |

- **A:** ส่วนที่ต่างราว 1% มาจากเวลารับส่งคำขอ 0.3–0.6 ms ต่อคำขอ เพราะ server จำลองถือคำขอไว้เฉลี่ย 50.2 ms จริง
- **C:** ที่ 64,168 คำขอต่อวินาที ตัวยิงโหลดใช้ CPU เต็มทั้ง 4 process แล้ว ตัวเลขนี้จึงเป็นเพดานของตัวยิงโหลดเองที่ N = 200
- **D:** Throughput ผ่าน NGINX ได้ 981.1 เทียบกับยิงตรง 986.8 คำขอต่อวินาที
- **E:** เกณฑ์ที่ผมใช้คือ (สูงสุด − ต่ำสุด) ÷ ต่ำสุด ของ Throughput และ p50 ส่วน p95 แกว่งกว่านั้นมาก (168.1 / 180.6 / 140.7 ms ต่าง 28%) และไม่ได้นับในเกณฑ์ ถ้าจะใช้ p95 ตัดสินระบบจริงควรวัดซ้ำหลายรอบ

**สิ่งที่ต้องแก้ระหว่างทาง**
- ไม่มีข้อไหนไม่ผ่าน
- เพิ่มช่อง `sent` ใน `loadgen.py` ให้รายงานจำนวนคำขอที่ส่งทั้งหมดรวมช่วงอุ่นเครื่อง เพราะเดิมรายงานเฉพาะช่วงที่วัด จึงเทียบกับ server จำลองในทดสอบ B ไม่ได้ ส่วนวิธีวัดเดิมไม่ได้แตะ
- เขียน `check_loadtest.py` เพิ่มเพื่อรันทดสอบ A–E ต่อเนื่องบนเครื่องเช่า และ `plot_loadtest_check.py` สำหรับวาดกราฟ
