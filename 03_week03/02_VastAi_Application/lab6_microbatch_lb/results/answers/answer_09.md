## สรุปผลแบบที่ 4 (GPU 2 ใบ · ใบละ 4 server · Micro-batching · NGINX Round Robin)

ความจุของแบบที่ 4 คือ **180 คน** (N=180 ผ่าน: p95 490.3 ms, error 0 จาก 8,299 คำขอ; N=183 ไม่ผ่านทั้งสองรอบ: p95 520.1 และ 514.0 ms) ตัวยิงโหลดรันเป็นงานเบื้องหลังในชื่อ `gpu2` และจบด้วย `DONE`

| # | จำนวน GPU | แบบ | ความจุ (N) | Throughput สูงสุด | p95 ที่ความจุ | เท่าของแบบที่ 3 | Efficiency |
|---|---|---|---|---|---|---|---|
| 1 | 1 | 1 server · ทีละ 1 รูป | 29 | 62.6 req/s | 494.4 ms | 0.32 | 0.32 |
| 2 | 1 | 1 server · Micro-batching | 52 | 142.9 req/s | 490.0 ms | 0.58 | 0.58 |
| 3 | 1 | 4 server · Micro-batching | 90 | 278.7 req/s | 468.4 ms | 1.00 | 1.00 |
| 4 | 2 | ใบละ 4 server · Micro-batching | 180 | 566.5 req/s | 490.3 ms | 2.00 | 1.00 |

**GPU 1 ใบ 90 คน → 2 ใบ 180 คน (2.00 เท่า)**

**คำขอกระจายไป GPU 2 ใบเท่ากันไหม**
- เท่ากัน: ที่ N=180 ได้ gpu0 4,149 คำขอ และ gpu1 4,150 คำขอ โดย server ทั้ง 8 ตัวได้ตัวละ 1,037–1,038 (12.5%)
- มีระดับเดียวที่ไม่เท่า คือ N=128 (ยังผ่าน, p95 476.1 ms): server `gpu0-8102` ได้ 277 คำขอ ส่วนอีก 7 ตัวได้ตัวละราว 1,027 และมี HTTP 502 2 ครั้ง (0.03%)
- สาเหตุของระดับนั้น: server ตัดการเชื่อมต่อ 2 ครั้ง แล้วค่าเริ่มต้นของ NGINX (`max_fails=1`, `fail_timeout=10s`) ถอด server ตัวนั้นออกจากวง 10 วินาที อาการเดียวกับที่เคยเห็นในแบบที่ 3 และผมไม่ได้แก้ค่า NGINX

**ถ้าได้ไม่ถึง 2 เท่า ส่วนไหนเป็นตัวถ่วง**
- รอบนี้ได้ครบ 2 เท่า (ความจุ 2.00 เท่า, Throughput 2.03 เท่า) จึงไม่เห็นตัวถ่วงร่วมระหว่าง GPU
- NGINX ใช้ CPU เพียง 12% และตัวยิงโหลด 19% ส่วน server 8 ตัวใช้รวม 1,090% จาก 64 core
- เพดานอยู่ที่ตัว GPU แต่ละใบ: GPU ทำงาน 83–85% และ Throughput นิ่งที่ราว 550–566 req/s ตั้งแต่ N=142 ถึง 512

**ข้อที่ต่างจากรอบวัดแบบที่ 3**
- เปิดระบบครั้งแรกล้ม: server 8 ตัวอุ่นเครื่องพร้อมกันแล้ว GPU 0 เกิด CUDA out of memory
- ผมแก้โดยจำกัดหน่วยความจำ GPU ต่อ server เป็น 0.85 ÷ จำนวน server ต่อ GPU (แก้ใน `cluster.sh` และ `server.py`) แล้วเปิดใหม่ได้ครบ 8 ตัวใน 15 วินาที
- แบบที่ 3 ไม่ได้วัดซ้ำด้วยค่าจำกัดนี้ ตัวเลข 2.00 เท่าจึงเทียบกับผลเดิม แต่ที่โหลดต่อ GPU เท่ากัน สองรอบให้ผลใกล้กัน (แบบที่ 3 อิ่มที่ 267–279 req/s, แบบที่ 4 อิ่มที่ 275–283 req/s ต่อใบ)
- ไม่ได้วัด N=181–182 ความจุจริงจึงอยู่ในช่วง 180–182

**เครื่องยังเปิดอยู่**: instance <id> (ป้าย `vapp-lab6-nginx` ราว $0.36/ชม.) ไม่ได้ destroy และระบบแบบที่ 4 ยังรันอยู่ (สถานะ OK)
