## สรุป LAB 6 · ส่วนที่ 1 (API ตรวจภาพบน GPU ใบแรก)

server 1 ตัวเปิดอยู่บน GPU ใบแรก (GPU 0) ในโหมดทีละรูป ส่งรูปพร้อม key ได้ผลครบทั้ง 6 รูป และส่งแบบไม่มี key ถูกปฏิเสธด้วย 401 ตามที่กำหนด **เครื่องยังเปิดอยู่** (instance <id> ป้าย `vapp-lab6-nginx` RTX 3090 2 ใบ) ไม่ได้ destroy และ GPU ใบที่สองยังว่าง

### โค้ด `code/server.py`
- **รับรูปและตรวจ key:** `POST /v1/detect` (ช่อง `file`) ตรวจ Bearer key ก่อนอ่านไฟล์ ไม่มีหรือผิดตอบ 401 แล้วถอดรูปและใส่คิว
- **ตัวหยิบงานตัวเดียว:** thread `inference-worker` ตัวเดียวทำทั้งโหลดโมเดล อุ่นเครื่อง และเรียกโมเดลทุกครั้ง จึงเรียกโมเดลได้ทีละครั้ง รูปที่มาระหว่างนั้นรอในคิว
- **สองโหมด (ตั้งด้วย `MODE`):** `single` หยิบครั้งละ 1 รูป ส่วน `micro` หยิบทุกรูปที่รออยู่ ไม่เกิน 32 รูป และถ้ายังไม่ครบจะรอเพิ่มได้ไม่เกิน 5 ms นับจากรูปแรก
- **อุ่นเครื่องก่อนพร้อม:** ตอนเปิดจะเรียกโมเดลด้วยรูปจำลองทุกขนาด ตั้งแต่ 1 รูปถึงจำนวนสูงสุดของโหมด เสร็จแล้วจึงเปิดพอร์ตและ `GET /health` ตอบ `ready`
- **ค่าที่ตรึง:** โมเดล `best.pt` ขนาดภาพ 640 ความมั่นใจขั้นต่ำ 0.35

### JSON จริง 1 ตัวอย่าง (sample-6.jpg ตัดให้เหลือ 2 จาก 9 วัตถุ)
```json
{"filename": "sample-6.jpg", "server": "gpu0-8001", "mode": "single", "batch_size": 1,
 "queue_ms": 0.06, "model_ms": 15.42, "image": {"width": 640, "height": 640}, "count": 9,
 "detections": [
  {"class_id": 5, "class_name": "Person",  "confidence": 0.8917, "box": {"x1": 380.1, "y1": 194.3, "x2": 480.3, "y2": 550.4}},
  {"class_id": 0, "class_name": "Hardhat", "confidence": 0.8858, "box": {"x1": 255.4, "y1": 124.3, "x2": 300.4, "y2": 168.7}}]}
```

| ช่อง | ความหมาย |
|---|---|
| `filename` | ชื่อไฟล์ที่ส่งมา |
| `server` | server ตัวไหนตอบ (GPU 0 พอร์ต 8001) |
| `mode` | โหมดของ server (`single` หรือ `micro`) |
| `batch_size` | รูปนี้เข้าโมเดลพร้อมกันกี่รูป |
| `queue_ms` | เวลารอคิว ตั้งแต่เข้าคิวจนเริ่มเรียกโมเดล (ms) |
| `model_ms` | เวลาที่โมเดลใช้ในการเรียกครั้งนั้น (ms) |
| `image` | ขนาดรูปต้นฉบับ (พิกเซล) |
| `count` | จำนวนวัตถุที่เจอ |
| `detections[]` | แต่ละวัตถุ: `class_id` / `class_name` คือคลาส, `confidence` คือความมั่นใจ, `box` คือกรอบ x1,y1,x2,y2 เป็นพิกเซลของรูปต้นฉบับ |

### ผลทดสอบบนเครื่อง
ทุกรูปตอบ 200 เข้าโมเดลครั้งละ 1 รูป และรอคิว 0.06–0.10 ms

| รูป | ขนาดไฟล์ | จำนวนวัตถุของแต่ละคลาส | เวลาโมเดล รอบ 1 / รอบ 2 (ms) |
|---|---|---|---|
| sample-1.jpg | 48,766 B (47.6 KB) | Person 6 · Hardhat 5 · NO-Safety Vest 5 · Safety Vest 1 · NO-Hardhat 1 (รวม 18) | 55.04 / 16.48 |
| sample-2.jpg | 51,119 B (49.9 KB) | Person 3 · Hardhat 2 · NO-Safety Vest 2 · NO-Hardhat 1 · Mask 1 (รวม 9) | 23.41 / 18.25 |
| sample-3.jpg | 54,382 B (53.1 KB) | Person 2 · NO-Safety Vest 2 · Hardhat 1 · NO-Hardhat 1 · NO-Mask 1 (รวม 7) | 18.04 / 16.14 |
| sample-4.jpg | 79,999 B (78.1 KB) | Hardhat 21 · Safety Vest 20 · Person 19 · NO-Mask 19 (รวม 79) | 16.86 / 15.86 |
| sample-5.jpg | 61,813 B (60.4 KB) | Person 2 · Hardhat 2 · Safety Vest 2 · vehicle 2 (รวม 8) | 17.89 / 18.97 |
| sample-6.jpg | 41,667 B (40.7 KB) | Person 3 · Hardhat 2 · Safety Vest 2 · NO-Mask 2 (รวม 9) | 15.42 / 16.81 |

- **เวลาโมเดล:** คำขอแรกสุด (sample-1 รอบ 1) ช้ากว่าปกติที่ 55 ms ทั้งที่อุ่นเครื่องแล้ว ยังไม่ได้หาสาเหตุ ส่วนรอบ 2 อยู่ที่ราว 16–19 ms ทุกรูป
- **การปฏิเสธ:** ไม่มี key, key ผิด และ scheme ที่ไม่ใช่ Bearer ตอบ 401 ทั้งหมด ไฟล์ที่ไม่ใช่รูปตอบ 400
- **`/health`:** ตอบ 200 `ready` โหมด `single` บน `cuda:0`
- **โหมด Micro-batching:** ลองเปิด server ชั่วคราวอีกตัวบน GPU 0 แล้วยิง 256 คำขอพร้อมกัน 64 สาย ได้ batch สูงสุด 32 รูป และจำนวนวัตถุของแต่ละรูปตรงกับโหมดทีละรูป คำขอเดี่ยวรอคิว 5.16 ms ตามเพดาน 5 ms ปิด server ตัวนี้แล้ว

### สิ่งที่ควรรู้
- server ฟังที่ `127.0.0.1:8001` ภายในเครื่องเท่านั้น ยังเรียกจากภายนอกไม่ได้ ผมเว้นพอร์ต 8080 ที่เปิดออกภายนอกไว้ให้ nginx ในขั้นถัดไป
- API key สุ่มสร้างใหม่ เก็บในไฟล์ `api_key.env` (สิทธิ์ 600) ทั้งในโฟลเดอร์งานและบนเครื่อง ไม่มีค่า key ในโค้ด ผลลัพธ์ หรือรายงานนี้
- บนเครื่องต้องเปลี่ยน `opencv-python` เป็น `opencv-python-headless` เพราะ image ไม่มี `libxcb`
