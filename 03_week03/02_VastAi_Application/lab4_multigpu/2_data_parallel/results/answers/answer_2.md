# สรุปผล Lab4 / 2_data_parallel — Qwen3-8B แปลงคำถามเป็น SQL ด้วย LoRA + DDP บน GPU 2 ใบ

งานครบทุกขั้น: หา batch, เทรน 3 Epoch ด้วย batch ต่อ GPU 4 และวัดผล Base กับทุก Epoch แล้ว
Exact Match บน Test Set ขึ้นจาก 0% (Base) เป็น 79.0% หลัง Epoch 3

เครื่อง `vapp-lab4-dp` ใช้ RTX 3090 24 GB × 2 ข้อมูลคือ Training Set 4,000 ตัวอย่าง และ Test Set 200 ตัวอย่าง

## batch ต่อ GPU เทียบ VRAM สูงสุด

ลองอย่างละ 3 step ด้วยตัวอย่างที่ยาวที่สุด (256 token) การ์ดมี 24,576 MiB ต่อใบ

| batch ต่อ GPU | ผล | VRAM สูงสุด GPU0 | VRAM สูงสุด GPU1 |
|---|---|---|---|
| 1 | ผ่าน | 18,227 MiB | 18,233 MiB |
| 2 | ผ่าน | 20,123 MiB | 20,123 MiB |
| 4 | ผ่าน | 24,075 MiB | 24,075 MiB |
| 8 | Out of Memory ทั้งสองใบ | — | — |

## การเทรน 3 Epoch

- **batch ที่ใช้:** 4 ต่อ GPU รวม 8 (500 step ต่อ Epoch รวม 1,500 step)
- **ความเร็วเฉลี่ย:** 0.419 วินาทีต่อ step หรือ 19.08 ตัวอย่างต่อวินาที
- **learning rate:** คงที่ 2e-4 ตลอด (AdamW) ไม่มี warmup หรือ decay

| Epoch | วินาทีต่อ step | ตัวอย่างต่อวินาที | GPU util GPU0 | GPU util GPU1 |
|---|---|---|---|---|
| 1 | 0.418 | 19.15 | 97.1% | 98.6% |
| 2 | 0.418 | 19.12 | 97.9% | 98.6% |
| 3 | 0.422 | 18.97 | 98.3% | 98.6% |

GPU util ของ Epoch 1 วัดเฉพาะ step 101–500 เพราะช่วงแรกอยู่ก่อนการรันต่อจาก checkpoint
หลังจบทุก Epoch น้ำหนัก LoRA ของ GPU ทั้งสองใบเท่ากัน

## loss และ Exact Match

| โมเดล | train loss เฉลี่ย | test loss | Exact Match | Exact Match แบบผ่อน |
|---|---|---|---|---|
| Base | — | 1.8453 | 0.0% (0/200) | 54.5% |
| หลัง Epoch 1 | 0.0885 | 0.0581 | 70.0% (140/200) | 72.0% |
| หลัง Epoch 2 | 0.0322 | 0.0520 | 77.5% (155/200) | 79.5% |
| หลัง Epoch 3 | 0.0205 | 0.0578 | 79.0% (158/200) | 81.0% |

- **Exact Match:** SQL ต้องตรงกับเฉลยทุกตัวอักษรหลังยุบช่องว่าง
- **แบบผ่อน:** ไม่สนตัวพิมพ์เล็กใหญ่ นับ `'` เท่ากับ `"` และไม่สน `;` ท้ายคำสั่ง (ตัวเลขนี้ผมเพิ่มเอง)
- **Base ได้ 0%:** ตอบเป็น SQL ถูกรูปแบบ แต่ใช้ single quote และคงตัวพิมพ์ใหญ่ของค่าไว้ ต่างจากเฉลย
- **test loss:** ต่ำสุดที่ Epoch 2 แล้วขยับขึ้นเล็กน้อยที่ Epoch 3 ขณะที่ Exact Match ยังเพิ่ม

## สิ่งที่ต่างจากแผนและควรรู้

- **เทรนรอบแรกล้มด้วย Out of Memory ที่ step 59** ทั้งที่ batch 4 ผ่านขั้นหา batch แล้ว batch ที่มี padding ใช้หน่วยความจำมากกว่า batch ทดสอบที่ไม่มี padding ผมแก้โดยไม่ส่ง attention mask ตอนเทรน แล้วรันใหม่ทั้งหมดตั้งแต่ขั้นหา batch ตัวเลขข้างบนมาจากรอบใหม่ล้วน
- **การไม่ส่ง mask ไม่เปลี่ยนผลในทางทฤษฎี** เพราะ pad ทางขวาและ attention เป็นแบบ causal ค่าที่วัดได้บน batch ทดสอบต่างกันเล็กน้อย: loss 1.6797 เทียบ 1.6786
- **batch 4 เหลือ VRAM น้อยมาก** ใช้ถึง 24,145 MiB จาก 24,576 MiB ในการเทรนจริง
- **มี 1 ตัวอย่างใน Training Set ที่ยาว 319 token** ถูกตัดเหลือ 256 ส่วน Test Set ไม่มีตัวอย่างใดเกิน
- **CUDA เปิดไม่ได้ตอนแรก** เพราะไลบรารีใน image บัง driver ของเครื่อง แก้ด้วยการตั้ง `LD_LIBRARY_PATH` ใน `run_all.sh`
- **วัดผลหลังเทรนจบทั้ง 3 Epoch** โดยใช้ adapter ที่บันทึกไว้ตอนจบแต่ละ Epoch ไม่ได้วัดคั่นระหว่างเทรน

## การรันต่อเมื่อการเชื่อมต่อหลุด

งานรันใน tmux บนเครื่อง GPU ผ่าน `run_all.sh` ซึ่งสั่งซ้ำได้ ขั้นที่เสร็จแล้วจะถูกข้าม และการเทรนบันทึก checkpoint ทุก 50 step กับทุกจบ Epoch
ผมทดสอบโดยหยุดงานเองที่ step ราว 140 แล้วสั่งใหม่ งานรันต่อจาก checkpoint step 100 และ log ต่อเนื่องครบ 1–1,500
ระหว่างรันผมรายงานความคืบหน้าทุก 2–3 นาที
