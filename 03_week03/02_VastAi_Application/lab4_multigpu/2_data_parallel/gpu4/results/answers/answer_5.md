เทรน Qwen3-8B ด้วย LoRA บน GPU 4 ใบ (DDP) ครบ 3 Epoch แล้ว Exact Match บน Test Set ขึ้นจาก 1.5% (Base) เป็น 76.5% หลัง Epoch 3 และเครื่อง `vapp-lab4-dp4` **ยังเปิดอยู่**

## 1. batch ต่อ GPU เทียบ VRAM สูงสุด
ลองอย่างละ 3 step ด้วยตัวอย่างที่ยาวที่สุด (256 token) ค่า VRAM อ่านจาก nvidia-smi และเท่ากันทั้ง 4 ใบ (ใบละ 24,576 MiB)

| batch ต่อ GPU | batch รวม | ผล | VRAM สูงสุดต่อใบ GPU0–GPU3 (MiB) | วินาที/step |
|---|---|---|---|---|
| 1 | 4 | ผ่าน | 18,266 | 0.28 |
| 2 | 8 | ผ่าน | 19,268 | 0.38 |
| 4 | 16 | ผ่าน | 22,340 | 0.69 |
| 8 | 32 | Out of Memory ทั้ง 4 ใบ | – | – |

Exact Match นับว่าตรงเมื่อ SQL เหมือนเฉลยทุกตัวอักษร หลังตัดช่องว่างซ้ำและ `;` ท้ายออก Base ได้ต่ำเพราะส่วนใหญ่ต่างจากเฉลยแค่ตัวพิมพ์และชนิดเครื่องหมายคำพูด ถ้าไม่นับสองอย่างนี้ Base ได้ 54.5% และหลัง Epoch 3 ได้ 78.5%

## สิ่งที่ควรรู้
- **batch 4 ล้มในการเทรนจริง 2 รอบแรก:** ผ่านการลอง 3 step ที่ 24,098 MiB แต่ Out of Memory ราว step 20–25 ทั้งสองรอบ รอบสองเปิด `expandable_segments` แล้วก็ยังล้ม
- **วิธีแก้:** คำนวณ loss เฉพาะ token ของคำตอบแทนทุกตำแหน่ง VRAM ที่ batch 4 จึงลดเหลือ 22,340 MiB แล้วลอง batch ใหม่ทั้งหมด ตารางข้างบนคือรอบสุดท้ายนี้ ส่วน log ของสองรอบที่ล้มเก็บไว้ใน `results/attempt1_default_allocator` และ `results/attempt2_expandable_segments`
- **Gradient เท่ากันทุกใบ:** 3 step แรกของการเทรน แต่ละใบได้ loss ต่างกัน (ข้อมูลคนละส่วน) แต่ผลรวม Gradient หลัง DDP เฉลี่ยตรงกันทั้ง 4 ใบ
- **ค่าที่เลือกเองนอกเหนือจากที่ตรึง:** learning rate คงที่ตลอด, AdamW ไม่มี weight decay, LoRA dropout 0, LoRA เก็บเป็น float32 ทับโมเดล bf16 ผ่าน autocast
- **ข้อมูล:** ใช้ชุดที่เตรียมไว้บนเครื่องแล้ว คือ b-mc2/sql-create-context สับด้วย seed 0 แบ่ง Train 4,000 และ Test 200 มีตัวอย่าง Train 1 รายการที่ยาว 322 token จึงถูกตัดเหลือ 256
- **การรันต่อเมื่อหลุด:** งานรันใน tmux บนเครื่อง ขั้นที่เสร็จแล้วจะถูกข้าม และการเทรนเริ่มต่อจาก Epoch ล่าสุดที่จบ ทดสอบแล้วโดยหยุดหลัง Epoch 1 แล้วรันต่อ ได้ loss ของ Epoch 2 เท่ากับรอบจริง (0.0386)
- **การรายงาน:** `train.log` มีบรรทัด `[REPORT]` ทุก 2 นาที และ `status.log` มีบรรทัดสถานะทุก 2.5 นาที ระหว่างรอบนี้ข้อความท้ายบรรทัดของ `status.log` ดึงมาผิดไฟล์ แก้ใน `run_all.sh` แล้วแต่ยังไม่ได้รันทั้งชุดซ้ำ
- **การวัดผล:** วัดทั้ง 4 จุดหลังเทรนจบ จาก adapter ที่บันทึกไว้ตอนจบแต่ละ Epoch ไม่ได้วัดแทรกระหว่างเทรน
- **น้ำหนัก adapter:** ไฟล์น้ำหนัก (Epoch ละ 15 MB) ยังอยู่บนเครื่องเท่านั้นที่ `/workspace/lab4_dp4/results/adapters` ถ้าจะปิดเครื่องต้องคัดลอกออกมาก่อน
