ลองอย่างละ 3 step ด้วยตัวอย่างที่ยาวที่สุด (256 token) ค่าเป็น GB ที่ PyTorch จองไว้สูงสุด

|---|---|---|---|---|---|---|
| 1 | 4.88 | 3.65 | 3.65 | 5.31 | 0.556 | ผ่าน |

GPU 3 เป็นคอขวด เพราะมี LM Head และการคำนวณ loss อยู่บนใบนี้ จึงเต็มก่อนใบอื่น ขณะที่ GPU 1 และ 2 ยังเหลือที่ว่าง

## ความเร็วและ GPU util ระหว่างเทรน

| Epoch | train loss | วินาที/step | ตัวอย่าง/วินาที | GPU 0 | GPU 1 | GPU 2 | GPU 3 |
|---|---|---|---|---|---|---|---|
| 1 | 0.1233 | 1.626 | 9.84 | 24.6% | 21.4% | 22.3% | 29.7% |
| 2 | 0.0382 | 1.620 | 9.88 | 24.8% | 24.7% | 25.2% | 30.0% |
| 3 | 0.0252 | 1.600 | 10.00 | 25.2% | 19.4% | 21.8% | 31.4% |

- **เวลาเทรน:** ประมาณ 400–406 วินาทีต่อ Epoch รวมราว 20 นาที
- **GPU util:** เฉลี่ยใบละ 20–30% เพราะทำงานทีละใบต่อกันเป็นทอด ใบที่เหลือรอ
- **VRAM ขณะเทรนจริง:** สูงสุด 11.91 / 9.90 / 9.90 / 18.96 GB (GPU 0–3) ไม่เกิด Out of Memory

## loss และ Exact Match บน Test Set (200 ตัวอย่าง)

| โมเดล | train loss | test loss | Exact Match |
|---|---|---|---|
| Base | – | 1.9176 | 1.5% (3/200) |
| หลัง Epoch 1 | 0.1233 | 0.0629 | 69.0% (138/200) |
| หลัง Epoch 2 | 0.0382 | 0.0536 | 77.5% (155/200) |
| หลัง Epoch 3 | 0.0252 | 0.0540 | 74.5% (149/200) |

- **Epoch 3 ไม่ดีกว่า Epoch 2:** train loss ยังลดลง แต่ test loss ไม่ลดต่อและ Exact Match ลดลง 3 จุด
- **Base ได้ต่ำ:** ตัวอย่างคำตอบที่ดูพบว่าใช้ `'...'` แทน `"..."` และขึ้นบรรทัดใหม่ ไม่ตรงรูปแบบเฉลย
- **เกณฑ์ Exact Match:** เทียบข้อความตรงตัว หลังยุบช่องว่างและตัด `;` ท้ายออก

## สิ่งที่ผมเลือกเองนอกเหนือจากค่าที่ตรึง

- **Optimizer:** AdamW, learning rate คงที่ 2e-4 ไม่มี scheduler, LoRA dropout 0
- **loss:** คิดเฉพาะส่วนคำตอบ SQL ไม่รวม prompt
- **การตัดความยาว:** มี 1 ตัวอย่างใน Training Set ที่ยาว 319 token ถูกตัดท้ายเหลือ 256 (คำตอบถูกตัดบางส่วน)
- **การถอดคำตอบตอนวัดผล:** greedy สูงสุด 160 token ใหม่
